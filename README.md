# TFC Планы

Таск-менеджер в стиле Minecraft для совместной игры в сборку на **TerraFirmaCraft 1.21.1**.
React + Vite + Firebase (Firestore, Anonymous Auth, AI Logic / Gemini).

## Что умеет

- **Список задач** с вкладками «Активные» / «Выполненные». Задача закрывается кружком слева, цвет кружка — важность.
- **Важность**: низкая, обычная, высокая, критическая.
- **«Что важнее?»** — попарное сравнение задач. Каждый выбор меняет Elo-рейтинг, и сортировка
  «По рейтингу» со временем отражает общее мнение. Помогает, когда важность трудно сравнить напрямую.
- **Создание и редактирование в одном окне**: название, важность, статус, группа, исполнитель, описание и ресурсы
  заполняются сразу. Кнопка «Создать с планом» сразу открывает документ.
- **Описание в Markdown** со ссылками на предметы: `[[tfc:metal/ingot/bronze|4]]` превращается в иконку,
  русское название и количество.
- **Чеклист ресурсов**: предмет и «собрано X из N» плюс обычные пункты. В строке задачи видно, что ещё собрать.
- **Документы (артефакты)** открываются панелью справа от списка, как артефакты в ИИ-чатах, или на всю
  страницу. Markdown-редактор, предпросмотр, автосохранение, вставка предметов.
- **Агент Gemini** внизу документа, в формате чата: быстрые запросы, свой вопрос, работа с выделенным
  фрагментом. Ответ можно добавить в конец, вставить в курсор, заменить им фрагмент или весь документ,
  а ресурсы из него — перенести в чеклист задачи.
- **Группы** задач с иконкой предмета, фильтры: поиск, важность, «мои».
- **Подпись ником** без регистрации: ник хранится в куке `tfc_nick`. Кнопка «Взять себе» назначает исполнителя.
- **Библиотека предметов**: 13 000+ предметов сборки с русскими названиями и иконками.
- **Справочник** (по данным jar): жилы руд с цепочкой обработки до металла, топливо, жидкое топливо (нефть,
  бензин, дизель, этанол, растительное масло, биодизель), еда, температуры металлов.
- **Карта мира TFC Real World**: обычный вид (атлас из высот мода) и тематические слои, клик — координаты точки,
  город ↔ координаты блока, расстояние и направление, места задач.
- **Замена блоков в схемах Create (.nbt)**: вручную, правилами или агентом; блок можно убрать из схемы целиком.
  В схему пишется ровно тот id, что есть в библиотеке предметов. **Библиотека схем**: общая, исходник + замены,
  скачивается уже с заменами, можно открыть и поправить или удалить.
- **Обновления сборки**: при деплое — запись о том, что поменялось в модах, и патчноут от модели.
- Светлая и тёмная тема (по системной настройке), палитра взята из Minecraft.

## Быстрый старт

```bash
npm install
npm run dev
```

При первом `dev`/`build` автоматически собирается библиотека предметов (`npm run items`, около минуты):
скачивается `client.jar` 1.21.1 с серверов Mojang и делается sparse-клон репозитория TFC.
Нужны `git` и интернет.

Без настроенного Firebase приложение работает в **локальном режиме**: данные лежат в `localStorage`
браузера, в шапке горит метка `offline`, Gemini выключен. Так удобно разрабатывать интерфейс.

## Firebase

Проект уже создан: **`tfc-plans-fd2c`** (`.firebaserc`). Включены Firestore (eur3), анонимный вход
(`firebase.json` → `auth`) и AI Logic с Gemini Developer API. Конфиг веб-приложения лежит в `.env.local`
(он не в git, но эти значения не секретные: веб-конфиг Firebase и так виден в браузере).

```bash
npm run deploy          # сборка + hosting + правила + auth
npm run deploy:rules    # только правила Firestore
```

Сайт: https://tfc-plans-fd2c.web.app

Как настроить новый проект с нуля через CLI:

```bash
firebase projects:create <id>
firebase apps:create web "TFC Plans Web" --project <id>
firebase apps:sdkconfig WEB <appId>          # → .env.local по образцу .env.example
firebase deploy --only firestore:rules       # заодно включает Firestore API
firebase firestore:databases:create "(default)" --location eur3
firebase deploy --only auth                  # анонимный вход
FIREBASE_CLI_EXPERIMENTS=ailogic firebase ailogic:providers:enable gemini-developer-api
```

После этого один раз откройте в консоли **AI Logic → Get started → Gemini Developer API**: только этот
шаг выдаёт Gemini-ключ. Без него агент отвечает ошибкой «genai config not found».

### App Check

Включён в режиме **Enforced** для Firestore, Authentication и AI Logic (сервис `firebaseml`).
Провайдер — reCAPTCHA Enterprise, ключ `VITE_RECAPTCHA_SITE_KEY`. Разрешённые домены ключа:
`tfc-plans-fd2c.web.app`, `tfc-plans-fd2c.firebaseapp.com` и `localhost`.
Если приложение откроют с другого домена, запросы будут отклоняться. Для отладки поставьте `VITE_APPCHECK_DEBUG=true`
и зарегистрируйте debug-токен из консоли браузера в Firebase Console → App Check.

Gemini-ключ (`Gemini API key (Firebase AI Logic)`, ограничен только Generative Language API) хранится на стороне
AI Logic и в код не попадает.

Модель Gemini задаётся в `VITE_GEMINI_MODEL` (по умолчанию `gemini-3.8-flash`).

> Про безопасность. Настоящей авторизации нет, так что любой, у кого есть ссылка на сайт, может читать и
> править задачи. Это сознательный выбор для игры с друзьями. App Check не даёт обращаться к базе и Gemini в обход сайта.

## Библиотека предметов

`scripts/build-items.mjs` создаёт:

- `public/items.json` — `[{ i: id, e: имя en, r: имя ru, t: путь иконки }]`;
- `public/icons/**.png` — текстуры, которые используются как иконки.

Иконка берётся из модели предмета: цепочка `parent` → `layer0` / `all` / `side` / …, сначала из текстур самого мода.
Для 3D-моделей без явной текстуры (мультиблоки IE) — текстура с тем же именем, что у предмета.
Для блоков это одна сторона, а не 3D-рендер. Текстуры, которые TFC генерирует в игре (дерево разных
пород, жидкости в вёдрах), заменяются базовыми.

Сгенерированные файлы **не коммитятся**: это ассеты Mojang и авторов модов. Пересобрать заново:
`npm run items -- --fresh`.

### Моды сборки (Create, Immersive Engineering и др.)

Скопируйте jar-файлы модов в папку [`mods/`](mods/) (можно всю папку `mods` из лаунчера) и выполните:

```bash
npm run deploy
```

Перед сборкой скрипт сверяет список jar с прошлым запуском. Если он изменился, библиотека пересобирается
сама: вытаскиваются названия (`en_us`, `ru_ru`), модели и иконки всех модов. jar-файлы в git не попадают.
Для локальной проверки: `npm run items`, потом `npm run dev`.

Если jar TerraFirmaCraft в `mods/` нет, TFC берётся с GitHub (`MOD_SOURCES` в скрипте).

## Вложения

Файлы задач (картинки, датапаки, скрипты) лежат в Firestore кусками — через пакет
[`firestore-files`](https://github.com/Jason1258t/firestore-files): Firebase Storage на бесплатном тарифе недоступен.
Коллекция, лимит (25 МБ) и правила доступа задаются в [`src/lib/files.config.ts`](src/lib/files.config.ts);
блок `files` в `firestore.rules` генерируется из него:

```bash
npm run rules:files     # после правки конфига
npm run deploy:rules
```

`scripts/migrate-files.mjs` перезаливает файлы, загруженные до перехода на пакет (добавляет контрольную сумму);
повторный запуск ничего не делает, `--dry-run` — только показать.

## Датапаки

Страница «Датапаки»: черновики хранятся в Firestore (`datapacks`), экспорт — zip под 1.21.1 (`pack_format` 48).

- **Рецепт по шаблону** — берётся JSON любого рецепта сборки и становится новым файлом в `data/<namespace>/recipe/`.
- **Замена** — файл по пути оригинала (`data/<ns>/recipe/<path>.json`) перекрывает рецепт мода.
- **Удаление** — по тому же пути кладётся `{"neoforge:conditions":[{"type":"neoforge:false"}]}` — так сам TFC отключает ванильные рецепты.
- **Файл** — произвольный путь (реестры, теги, конфиги модов в датапаке).
- zip можно скачать или сразу приложить к задаче.

Каталог рецептов (`public/recipes.json`, ~21 тыс.) собирается тем же `npm run items` из папок `data/*/recipe/` в jar
и `client.jar`. Рецепты, которые KubeJS сборки меняет скриптами, в каталоге будут в исходном виде.

### KubeJS сборки

Скрипты KubeJS удаляют и меняют рецепты при загрузке — и рецепты модов, и рецепты из датапаков, в том числе нашего.
Чтобы это было видно на сайте, папку `kubejs` инстанса импортируют:

```bash
npm run kubejs -- ~/Downloads/kubejs.zip                  # слой pack — kubejs сборки
npm run kubejs -- ~/Downloads/kubejs_world.zip --layer world  # ещё слой — скрипты сервера/мира
npm run kubejs                                            # пересобрать public/kubejs.json из импортированного
```

- Папка копируется в `instance/kubejs/<слой>/` (в git не хранится), повторный импорт слоя заменяет прошлый.
- `server_scripts` **выполняются в песочнице Node** (`node:vm`), а не разбираются регулярками: `ServerEvents.recipes`
  отдаёт записывающий `event`, остальное API KubeJS — заглушки. Так циклы, массивы id, шаблонные строки и константы
  из соседних файлов дают ровно те фильтры, что увидит игра. Каждое `event.remove` / `replaceInput` / `replaceOutput`
  сохраняется с файлом и строкой (у удалений циклом — ещё и строка массива с самим id).
- `custom` / `shaped` / `shapeless` / `recipes.<мод>.<тип>` — добавленные скриптами рецепты, `kubejs/data` —
  обычный датапак: всё это попадает в каталог.
- Семантика фильтров (`src/lib/recipeFilter.ts`) — как в KubeJS 2101: строка — id, RegExp, массив — ИЛИ,
  объект — И по `id` / `type` / `mod` / `group` / `input` / `output` плюс `or` и `not`. Теги на входе/выходе
  не раскрываются: `output: 'x'` совпадёт только с рецептом, где `x` указан явно.

**Страница «Рецепты»** — поиск по всему каталогу без лимита выдачи, фильтр по статусу (работают, удалены KubeJS,
изменены, добавлены скриптами, из `kubejs/data`), из неё рецепт уходит в выбранный датапак. В редакторе датапака
рецепты, которые удалит KubeJS, отмечены «KubeJS удалит».

**Конструктор** (у рецепта, который режет KubeJS):

- _Снять ограничение_ — готовая правка скрипта сборки: удалить строку с id или добавить в фильтр `not: { id }`.
- _Новый рецепт на основе_ — другой id в датапаке (если удаление только по id; проверка нового id — сразу) или
  KubeJS-скрипт с `event.custom(...)`. Скрипт работает при любом фильтре: `RecipesKubeEvent.remove` перебирает только
  рецепты из датапаков (`originalRecipes`), добавленные в событии — отдельный список. Кнопка «KubeJS-скрипт»
  в редакторе выгружает так весь датапак.

### Подсказки по типам рецептов

Коллекция `recipeHints` (id = тип, где `:` → `__`, `/` → `--`). Первичное наполнение — `scripts/recipe-hints.json`
(40 самых частых и нужных типов), заливается так:

```bash
node scripts/seed-recipe-hints.mjs
```

Скрипт не трогает подсказки, которые правили люди или агент (`--force` — перезаписать). Если подсказки для типа
нет (например, сборка обновилась), в редакторе есть «Составить агентом»: Gemini получает статистику полей по всем
рецептам этого типа в сборке и несколько реальных примеров и пишет подсказку; её можно поправить руками.

### Нагрев в чаше Create (WoodenCog)

Температура источника под чашей берётся из реестра датапака `data/woodencog/woodencog/temperature/block_temperature.json`
(блок → °C; файл заменяется целиком, читается при запуске сервера). Горелка Create — из
`config/woodencog-common.toml` (`blaze_burner_kindled` = 1350 °C по умолчанию; чугун плавится при 1535 °C).

## Справочник

Страница «Справочник» собирается из jar сборки скриптом `scripts/reference.mjs` (часть `npm run items`):

- **Руды** — конфиги жил (`worldgen/configured_feature/vein`): породы, высоты, редкость, доли сортов, признак
  на поверхности.
- **Цепочка до металла.** В сборке `tfcorewashing` отключает прямую плавку руд, поэтому для каждой руды
  строится кратчайший путь по рецептам (основные выходы) до предмета с `tfc:heating` в жидкий металл.
- **Топливо, еда, металлы** — `tfc/fuel`, `tfc/food`, `tfc/fluid_heat`; ингредиенты-теги раскрываются по тегам
  предметов всех модов.
- **Жидкое топливо** — семейства по тегам жидкостей `c:*` (этанол IE и CDG — одно семейство): двигатели
  Create: Diesel Generators (`fuel_type`), генератор IE (`generator_fuel`), горелки Create Liquid Fuel и все рецепты
  с этой жидкостью на выходе. Рецепты, которые удаляют датапаки сайта, помечены. Про нефть — как CDG считает запас
  чанков (шум по сиду, пороги из конфига по умолчанию).

Переопределения на сервере (датапаки, KubeJS) справочник не видит.

## Обновления сборки

`npm run items` пишет снимок `public/pack-manifest.json`: моды с версиями и sha1 jar, id предметов,
отпечатки рецептов (FNV-1a JSON). При деплое хостинга (`predeploy` в `firebase.json`) `scripts/pack-release.mjs`
сравнивает его с опубликованным на сайте и, если сборка изменилась, создаёт в Firestore `packUpdates/{id}`:

- моды: добавлены / убраны / обновлены (было → стало), ченджлоги с Modrinth по sha1 jar;
- предметы и рецепты: добавлены / удалены / изменены, новые типы рецептов.

Страница «Обновления» показывает ленту и датапаки сайта, которые затронуло обновление. Патчноут от модели
пишется при первом открытии свежего обновления и сохраняется; его можно перегенерировать или поправить руками.
`SKIP_PACK_RELEASE=1` — пропустить шаг, `node scripts/pack-release.mjs --dry-run` — посмотреть разницу.
Записи датапаков помнят отпечаток исходного рецепта, и редактор датапака предупреждает, если мод его поменял.

## Карта мира

Формулы проекции перенесены из мода TFC Real World один в один (`src/lib/projection.ts`): Equal Earth,
`horizontal_scale`/`vertical_scale` — радиус карты в блоках, за краями мир повторяется зеркально.
Города, регионы и карты-картинки профилей берутся из jar мода (`scripts/geo.mjs` → `public/geo.json`, `public/geo/`).

Профиль, масштабы и центр спавна нашего мира берутся из **импортированного конфига сервера**
(`config/server__tfc_real_world__server.toml`, см. ниже). Сейчас на сервере `horizontal_scale = 100000`,
`vertical_scale = 50000` — около 200 м на блок по экватору (Лондон — Париж ≈ 1900 блоков); спавн — у Милана (45.47° с. ш., 10.94° в. д.), он отмечен на карте.
Если конфиг не импортирован, действуют ручные настройки `settings/world` (шестерёнка на странице карты).

## Конфиги сервера

Скрипт `scripts/import-config.mjs` разбирает TOML-конфиги модов и сохраняет их в Firestore, в коллекцию `config` —
сайт читает настройки оттуда, а не из ручного ввода.

```bash
npm run config -- ~/Downloads/serverconfig.zip
```

- Вход — zip или папка. Путь конфига считается от `serverconfig/`, `config/` или `defaultconfigs/`
  (`serverconfig/tfc_real_world/server.toml` → `tfc_real_world/server.toml`).
- Один файл — один документ `config/{scope}__{путь, где / → __}`:
  `{ scope, path, mod, values, sha1, source, importedBy, importedAt }`, `values` — разобранный TOML без комментариев.
  Повторный импорт перезаписывает документ целиком.
- `--scope <имя>` — чьи это настройки (по умолчанию `server`). Например, клиентские конфиги конкретного игрока:
  `npm run config -- ~/instance/config --scope jason --only cold_sweat`.
- `--only <подстрока пути>` — только подходящие файлы (можно несколько раз), `--dry-run` — показать без записи.
- Пишет от имени залогиненного `firebase login` (как `pack-release`); сайту коллекция доступна только на чтение.
- Чтение на сайте: `useModConfig(path, scope)` и `configValue(c, 'раздел.ключ', 'number')` из `src/lib/config.ts`.

Что сейчас используется: `tfc_real_world/server.toml` — карта мира (`map_settings.map_profile`,
`generation_modes.horizontal_scale`/`vertical_scale`, `spawn_settings`). `tfc_eratosthenes-server.toml` сохранён
для справки: Eratosthenes берёт масштаб у TFC Real World и проецирует так же (`TFC_REAL_WORLD_FULL_WORLD`).

## Модель данных (Firestore)

| Коллекция     | Поля                                                                                                                                                                             |
| ------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `tasks`       | `title`, `description` (md), `status`, `priority` 0–3, `rating` (Elo), `checklist[]`, `icon`, `groupId`, `author`, `assignee`, `place` ({x, z, label}), `createdAt`, `updatedAt` |
| `groups`      | `name`, `icon`, `order`, `author`, `createdAt`                                                                                                                                   |
| `artifacts`   | `title`, `content` (md), `taskId`, `author`, `updatedBy`, `createdAt`, `updatedAt`                                                                                               |
| `files`       | вложения — пакет firestore-files (метаданные + `chunks/{n}`)                                                                                                                     |
| `datapacks`   | `name`, `namespace`, `description`, `entries[]` (`path`, `content`, `kind`, `sourceRecipe`, `sourceHash`)                                                                        |
| `schematics`  | библиотека схем: `name`, `fileName`, `fileId` (исходник в `files`), `replace[]` ({from, to}, `#remove` — удалить)                                                                |
| `recipeHints` | подсказки по типам рецептов: `title`, `body`, `source`                                                                                                                           |
| `packUpdates` | записи об обновлениях сборки (создаёт деплой), `notes` — патчноут                                                                                                                |
| `config`      | конфиги модов из `npm run config`: `scope`, `path`, `mod`, `values` (TOML), `importedBy`, `importedAt`                                                                           |
| `settings`    | `world`: профиль и масштабы мира TFC Real World                                                                                                                                  |

Пункт чеклиста: `{ id, text, itemId?, qty?, got?, done? }`. Если есть `itemId`, это ресурс «собрано got из qty»,
иначе обычная галочка.
