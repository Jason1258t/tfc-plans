# Программа `tfc`

Программа для ПК: держит папку игры в том же виде, что и сборка на [сервере сборки](pack-server.md).

- **Игроку** — докачивает и обновляет моды, конфиги, скрипты KubeJS и ресурспаки, а с сайта ставит датапаки,
  скрипты и схемы.
- **Хосту** — заливает новую версию сборки, раздаёт ключи, пересобирает данные сайта и выкладывает их.

Это не окно, а команды в терминале. Отдельного окна пока нет: оно в планах на потом.

- Код — [cli/](../cli/). Подробная инструкция с каждым флагом — [cli/README.md](../cli/README.md).
- Справка в самой программе — `tfc` без команды.
- Зачем и как устроено — [plans/pack-cli.md](plans/pack-cli.md).

## Установить

Три способа, выберите один. На сайте, раздел «Обновления» (https://tfc-plans-fd2c.web.app/updates), блок
«Программа tfc» показывает то же самое для вашей системы, с кнопкой «Копировать».

**1. Одной командой (проще всего).** Скачает программу, сверит контрольную сумму, поставит в свою папку
(Windows — `%LOCALAPPDATA%\Programs\tfc`, macOS и Linux — `~/.local/bin`) и пропишет её в PATH. Права администратора
не нужны.

- **Windows** — в PowerShell (Win + X → «Терминал»):

  ```powershell
  irm https://tfc-plans-fd2c.web.app/tfc/install.ps1 | iex
  ```

- **macOS, Linux** — в Терминале:

  ```bash
  curl -fsSL https://tfc-plans-fd2c.web.app/tfc/install.sh | sh
  ```

**2. Скачать файл.** Один файл, Node.js не нужен:

| Система            | Файл                                                                  |
| ------------------ | --------------------------------------------------------------------- |
| Windows            | https://tfc-plans-fd2c.web.app/tfc/tfc-win-x64.zip (внутри `tfc.exe`) |
| macOS, Apple M1–M4 | https://tfc-plans-fd2c.web.app/tfc/tfc-macos-arm64.zip                |
| macOS, Intel       | https://tfc-plans-fd2c.web.app/tfc/tfc-macos-x64.zip                  |
| Linux              | https://tfc-plans-fd2c.web.app/tfc/tfc-linux-x64.zip                  |

- **Windows:** распакуйте и запустите `tfc.exe` двойным кликом — программа предложит поставить себя, Enter. Если
  Windows пишет «защитила ваш компьютер» — «Подробнее» → «Выполнить в любом случае»: у файла нет платной подписи.
- **macOS:** в Терминале `xattr -d com.apple.quarantine ~/Downloads/tfc` (снять метку «скачано из интернета», файл
  без подписи Apple), потом `~/Downloads/tfc install`.
- **Linux:** `chmod +x ~/Downloads/tfc`, потом `~/Downloads/tfc install`.

`tfc install` можно и не делать: тогда команды пишутся из папки с файлом — `.\tfc.exe …` (Windows) или `./tfc …`.

**3. Через npm** — если уже стоит Node.js 20 или новее. Пакет меньше мегабайта:

```bash
npm install -g https://tfc-plans-fd2c.web.app/tfc/tfc.tgz
```

После установки **откройте новое окно терминала** — в нём команды пишутся просто `tfc …`. Убрать программу —
`tfc uninstall` (настройки и ключ останутся; для npm — `npm uninstall -g tfc-plans`).

Версия — `tfc --version`. Раз в сутки программа сама смотрит на сайте, нет ли новой, и подсказывает. Обновить —
`tfc --upgrade`: файл скачается, сверится, пробно запустится и только потом заменит старый (пакет npm обновит сам npm).
Настройки и ключ при обновлении сохраняются.

**Как это устроено.** Установщики (`cli/install/install.ps1`, `install.sh`) только скачивают файл и вызывают
`tfc install` — копирование и PATH делает сама программа (`cli/lib/install.mjs`): на Windows — PATH пользователя в
реестре, на macOS и Linux — строка с пометкой `# tfc install` в `~/.zshrc`, `~/.bash_profile` (macOS) / `~/.bashrc`,
`~/.profile` или `conf.d/tfc.fish`. Пакет npm `tfc-plans` — тот же код одним `.mjs`, собирает его `npm run tfc:dist`
(`tfc.tgz` рядом с zip). В реестр npm он не выложен; выложить — `npm publish dist-tfc/tfc.tgz` (нужен свой аккаунт npm),
тогда ставить можно будет и как `npm install -g tfc-plans`.

## Игроку

Нужен ключ: его выдаёт хост командой `tfc admin invite <ваш ник>`.

```bash
tfc init            # выбрать папку игры (версию) и мир — программа сама ищет их в лаунчерах
tfc login tfc_…     # войти ключом
tfc status          # что изменится — ничего не меняет
tfc pull            # докачать и обновить всё (закройте игру; спросит подтверждение)
tfc undo            # вернуть как было до прошлого pull
```

- `tfc init` находит версии в Prism Launcher, MultiMC, CurseForge, Modrinth и ATLauncher. Если нужной в списке нет,
  укажите папку, где лежит `mods/`.
- **Что приносит `tfc pull`:**
  - сборку с сервера сборки: моды, конфиги, KubeJS, ресурспаки, с выбранным миром — его датапаки;
  - аддоны сборки (вкладка «Аддоны» на сайте);
  - с сайта: скрипты KubeJS с отметкой «Ставить на сервер», датапаки с отметкой «Ставить в мир» (если выбран мир),
    библиотеку схем.
- **Только часть:** `tfc pull mods`, `tfc pull config kubejs`. Части: `mods` (с аддонами), `config`, `kubejs`,
  `resourcepacks`, `datapacks`, `world` (календарь мира), `schematics`, `addons`.
- **Одно названное с сайта:** `tfc pull datapacks "Фикс"` (любой датапак, в том числе тестовый),
  `tfc pull schematics Дом`, `tfc pull addons rw-host-fix`.
- Раньше команда называлась `tfc sync`. Старое имя пока работает и подсказывает новое.

**Что `pull` не делает с вашими файлами:**

- **Свои моды** (миникарта, шейдеры) не удаляются: программа убирает только то, что ставила сама.
  - Исключение — старая версия мода из сборки или аддона под другим именем файла. Её программа уберёт (с копией):
    с двумя jar одного мода игра не запустится.
- **Изменённые вами конфиги и скрипты** не затираются: новая версия ложится рядом как `*.tfc-new`.
  Перезаписать всё — `tfc pull --force`.
- **Клиентские настройки** (`*-client.toml`, `*-client.snbt` и т. п.: интерфейс, клавиши) только добавляются, если их нет.
- **Ваши правки конфигов** остаются молча, пока в сборке этот файл не поменяют. Если игра сама переписала файл
  (дату в шапке, пустые строки), это не считается вашей правкой: файл просто обновится.
- **Состояние модов** (кеши EMI, история JEI, журнал spark и т. п.) не ставится и не убирается.
- **Всё заменённое и убранное** сохраняется в `.tfc/backup/`. Вернуть как было — `tfc undo`
  (хранятся последние 5 раз).
- **Загрузка:** в несколько потоков, мелкие файлы (конфиги, скрипты) — пачками по одному запросу. Оборванная
  продолжается с места обрыва, каждый файл сверяется по контрольной сумме. Скачанное лежит в общем кеше: второй
  профиль и переустановка не качают сборку заново.
- Если на сайте сняли отметку, следующий `tfc pull` уберёт этот файл. Убирается только то, что поставила сама
  программа, и только если вы файл не меняли.

**Сборка и сайт не спорят за файл:**

- **У аддонов главный сайт.** Другую версию того же аддона из сборки программа не ставит. Файлы, которые аддон
  заменяет (например, `rw-host-fix` — скрипт `kubejs/server_scripts/event/eratosthenes_portal_clamp.js`), тоже
  не ставятся, а если уже стоят — уходят в копию. Перед заменами программа покажет список и спросит; без вопроса —
  `--yes`. Ключ для аддонов не нужен: `tfc pull addons` работает и без него.
- **У датапаков сайта главный сайт.** Они ставятся как `<мир>/datapacks/tfc-plans-<id>.zip` и в сборку не
  заливаются: `tfc publish` пропускает и их, и копии, скачанные с сайта кнопкой «Скачать» (`Фикс_магмы.zip`), если
  датапак отмечен «Ставить в мир». Такую ручную копию рядом с поставленной `tfc pull` убирает (с копией в
  `.tfc/backup/`): с двумя версиями одного датапака в мире правка на сайте не доходила бы до игры. Если датапак
  сайта уже лежит в сборке (заливали раньше), `pull` берёт его с сайта, а не из сборки. Свои датапаки хоста,
  которых нет на сайте, идут через сборку, как раньше.
- **У скриптов главная сборка.** Если хост уже залил скрипт в сборку, он приходит из сборки.

## Хосту

Нужен ключ администратора. Первый выдан при установке сервера сборки, остальные — `tfc admin invite <ник> --admin`.

**Залить новую версию сборки** — с ПК, где стоит игра, лучше из **клиентской** папки (игрокам нужны и клиентские
моды):

```bash
tfc init --instance "<клиентская папка игры>" --world "<мир>" --server-dir "<папка сервера>"
tfc login tfc_…
tfc status                                   # чем папка отличается от сборки на сервере
tfc publish --note "обновил Create до 6.0.4"  # залить; сборка сразу станет текущей для всех
```

- Заливаются только файлы, которых на сервере ещё нет.
- Шум не заливается: кеши и состояние модов, а также файлы, где игра поменяла только дату, пустые строки или время
  мира. `publish` покажет, какие файлы оставил в версии сервера. Подробно —
  [pack-server.md, «Шум»](pack-server.md#шум-что-не-заливается).
- Что берётся из папки, а что никогда не заливается — в [README сервера](../server/pack-server/README.md#что-можно-класть-в-снимок).
- Залить без переключения игроков — `tfc publish --no-current`, проверить, потом `tfc admin use <id>`.
- Если сборку меняли с другого устройства, `publish` не затрёт это молча. Он покажет изменённые файлы и попросит
  сначала забрать их (`tfc pull config`) или залить поверх (`--force`).
- **Аддоны и отмеченное на сайте** игроки получают сами, через `tfc pull`, — перезаливать сборку ради этого не нужно.
  `tfc publish` после своего `tfc pull` нужен, чтобы сервер сборки пересобрал данные сайта (рецепты, предметы)
  с новыми аддонами и скриптами.
- Скрипты KubeJS, которые выполняет сервер Minecraft, должны лежать в `kubejs/server_scripts/` заливаемой папки.
  Сервер сборки видит только залитое; если скриптов там не будет, сайт потеряет их рецепты.

**Версии сборки и ключи:**

| Команда                          | Что делает                                                      |
| -------------------------------- | --------------------------------------------------------------- |
| `tfc admin history`              | версии сборки (снимки)                                          |
| `tfc admin rollback`             | откатить игроков на прошлую версию                              |
| `tfc admin use <id>`             | сделать текущей конкретную версию                               |
| `tfc admin invite <ник>`         | ключ игрока (`--admin` — администратора); показывается один раз |
| `tfc admin keys` / `revoke <id>` | список ключей / отозвать                                        |

**Данные сайта.** После `publish` сервер сам собирает предметы, рецепты, карту и разбор KubeJS, а затем **пробно**
сравнивает их с сайтом. На сайт они попадают только по команде хоста:

```bash
tfc admin jobs                 # задания сервера: что собиралось, получилось ли
tfc admin jobs last            # последнее подробно: лог и что изменилось бы на сайте
tfc admin publish --live       # выложить на сайт — спросит подтверждение
tfc admin rebuild --pull       # пересобрать данные (свежий код сайта) — например, после правки разборщиков
```

- Выложить можно только **текущую** сборку.
- Команды сборки и публикации ждут конца задания и показывают лог. По Ctrl+C программа перестаёт смотреть,
  а задание на сервере продолжается.
- Посмотреть данные сайта локально до заливки — `tfc build`. Работает только из папки проекта, в скачанном файле
  этой команды нет.

**Правки конфигов от Claude.** Claude читает настройки сборки через MCP и может предложить правку
(`config_propose`): она ложится в базу сайта и ждёт хоста, файлы на ПК сама не меняет.

```bash
tfc admin changes              # что предложено: зачем, какие ключи, было → станет
tfc admin changes pull         # внести: покажет, в каких файлах что поменяется, и спросит
tfc admin changes reject <id>  # отклонить
```

- Правка ложится во все копии файла: `config/` и `defaultconfigs/` папки игры и папки сервера (`--server-dir`
  из `tfc init`), для `serverconfig/` — ещё и `<мир>/serverconfig/`. Меняется только значение ключа — комментарии
  и порядок остаются.
- Если в файле не то значение, которое видел Claude (вы меняли после выкладки сборки), программа это покажет.
  Если ключ ещё и в `serverconfig/` и перекрывает правку — тоже.
- Старые файлы — в копию, вернуть: `tfc undo`. `--dry-run` — только показать, `--yes` — не спрашивать.
- Итог (что применено, где, что не вышло) уходит обратно: Claude видит его в `config_changes`.
- Дальше: перезапустить сервер Minecraft, `tfc publish` (игроки получат конфиг) и `tfc admin publish --live`
  (сайт и Claude увидят новые значения).

**Папка сервера Minecraft.** Профиль на папке, где лежит `server.properties`, по умолчанию не трогает моды сборки:
серверу клиентские моды не нужны. Аддоны (серверные и общие) ставятся, моды сборки — явно, командой `tfc pull mods`.

Несколько папок игры — несколько профилей:

- создать: `tfc init --profile тест`;
- переключиться: `tfc use тест`;
- выполнить одну команду с другим профилем: `--profile тест`.

## Где что лежит

| Что                           | Где                                                                                                                                                                       |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Настройки и ключ              | macOS и Linux — `~/.config/tfc/config.json`, Windows — `%APPDATA%\tfc\config.json` (читает только владелец)                                                               |
| Что ставила программа         | `<папка игры>/.tfc/state.json`                                                                                                                                            |
| Копии заменённого и убранного | `<папка игры>/.tfc/backup/` (последние 5)                                                                                                                                 |
| Кеш контрольных сумм          | `<папка игры>/.tfc/hashes.json`                                                                                                                                           |
| Скачанные файлы сборки        | общий на все профили: Windows — `%LOCALAPPDATA%\tfc\cache`, macOS — `~/Library/Caches/tfc`, Linux — `~/.cache/tfc`; чего нет в сборке и не нужно 14 дней — убирается само |
| Исходники схем с сайта        | `<папка игры>/.tfc/site-files/`                                                                                                                                           |

Сервер по умолчанию — `https://tfc-pack.duckdns.org:28788`. Другой адрес задаётся так: `tfc login <ключ> --server <адрес>`.

## Разработчику

- Из папки проекта (Node.js 22+) программа запускается так: `npm run tfc -- <команда>`.
- Собрать файлы для всех систем — `npm run tfc:dist`. Результат ложится в `dist-tfc/` и `public/tfc/`
  (zip и `version.json`, в git их нет).
- Игрокам файлы уходят обычным деплоем сайта: `npm run deploy:site`.
- Собирать нужно на Mac: файлы для macOS подписываются локальной подписью, без неё Apple Silicon их не запустит.
- Версия — дата и хеш последнего коммита, который менял `cli/`. Поэтому пересборка без правок программы не заставит
  игроков обновляться.

Подробности сборки — в [cli/README.md](../cli/README.md#собрать-файлы-для-игроков-разработчику).

## Что пока не проверено

На 2026-10-20 (подробнее — в [итогах](plans/pack-cli-summary.md#что-не-проверено)):

- `tfc.exe` на Windows и файл для Linux ни разу не запускались. Файлы для macOS проверены.
- На настоящей папке лаунчера хоста `tfc init` и `tfc publish` ещё не запускались.
- Что после `tfc pull` игра запускается и заходит на сервер, не проверялось.
- На сервере сборки ещё нет текущей сборки и ключей игроков, поэтому игрокам пока нечего синхронизировать.
