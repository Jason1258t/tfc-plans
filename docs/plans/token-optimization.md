Оценка токенов — примерно 3.5 символа на токен (для русского/английского текста; для JSON порядок тот же).

## 2. Схемы индексации контекста

Идея: платить токены за контекст только когда он нужен и по минимальной «карте», а не за чтение файлов целиком.

### 2.1. Токен-бюджеты в `docs/STATE.md`

В таблице тем добавить столбец с размером и условием «когда читать»:

```markdown
| Файл | Что внутри | ~ток. | Читать когда |
| [site.md](state/site.md) | разделы сайта | 9.8k | задача трогает разделы сайта |
```

Агент по одной таблице решает, открывать тему или нет. Дешёвое изменение (несколько строк), убирает лишние
чтения больших тем.

### 2.2. Разбить тяжёлые темы

`docs/state/site.md` (9.8k) — не «тема», а каталог. Разбить по разделам (задачи/схемы/карта/справочник) или
сделать в нём вторичный индекс с указанием смещений. То же — `infra.md` (6.3k).

### 2.3. Убрать дубль `docs/agents.md`

На регистронезависимой ФС (macOS по умолчанию, Windows) файл `docs/agents.md` подхватывается гарнессами как
вложенный `docs/AGENTS.md` и грузится каждый раз (~1.5k ток.), хотя его содержимое уже упомянуто в корневом
`AGENTS.md` (проверено: на этой машине харнесс прислал `docs\AGENTS.md` с тем же текстом, что и `docs/agents.md`).
Предложение: переименовать в `docs/other-agents.md` и поправить ссылку в `AGENTS.md`. Экономия ~1.5k ток./сессию
без потери информации.

### 2.4. Новый инструмент `repo_brief` (индекс контекста)

MCP-инструмент `repo_brief(тема|задача)`, по ключевым словам возвращающий компактный набор: какие файлы читать
(с путями и размерами), какие MCP-инструменты использовать, какие скиллы загрузить. Один вызов вместо чтения
`STATE.md` + угадывания. Индекс держать статически (файл в репозитории), не тратя Firestore-чтения.

## 3. Оптимизация запросов к репозиторию

Текущий MCP уже экономит (пейджинг, маски полей Firestore, кеши, короткие ответы, «дальше: offset=…»). Дальше:

### 3.1. Сократить `tools/list` (главный рычаг, ~17k → ~10k)

- **Убрать `offset`/`limit` (`paging`) из каждой схемы** — это универсальное соглашение; описать один раз в
  `INSTRUCTIONS` («все списки принимают offset/limit и возвращают „дальше: offset=…“»). Сейчас `paging`
  повторяется в ~40 схемах. Экономия ~2–3k.
- **Короче описания параметров**: поле `description` часто повторяет имя параметра (`query` → «words»). Убрать
  пустые/повторяющие описания, оставить только неочевидные. Экономия ~1–2k.
- **Разбить сервер на ядро и специализированные секции** (см. 4.1): модель получает только нужные инструменты.

### 3.2. Пакетные инструменты

Добавить «многие за один вызов» там, где агент делает N вызовов: `items_batch(ids[])`, `recipes_batch(ids[])`.
Меньше round-trip'ов и меньше повторяющихся префиксов в ответах.

### 3.3. Компактная карта кода

Вместо `grep` по репозиторию (большие дампы) — инструмент `repo_map(query)` (или расширение `code_refs` на
код сайта): возвращает `файл:строка` с одним-двумя словами контекста, а не куски строк.

## 4. Новые MCP-инструменты и системы менеджмента/тестирования

### 4.1. Подмножество инструментов по секциям (`TFC_TOOLS`)

`server.mjs` принимает `TFC_TOOLS=core,site,map,…` и регистрирует только эти секции. Конфиги агентов подключают
нужное:

- **ядро** (`items/recipes/tags/reference/guides/jar/bytecode/code/books/blocks/loot`) — ~80% сессий;
- **site** (задачи/доки/датапаки/схемы/скрипты) — работа с сайтом;
- **map / addons / candidates / resources / logs** — по надобности.

Один и тот же код, просто меньше инструментов в `tools/list`. Это главная экономия постоянных расходов.

### 4.2. `repo_brief` (см. 2.4) — система менеджмента контекста.

### 4.3. `mcp_stats` — инструментирование расхода

Лёгкий локальный лог в MCP-сервере (размеры ответов и число вызовов по инструментам, в stderr/файл). Инструмент
`mcp_stats` выводит топ инструментов по «токен-минутам» — находит утечки объективно, а не на глаз.

### 4.4. `verify` — тестирование без длинных дампов

Инструмент, который прогоняет `npx tsc -b` / `npx oxlint src scripts` (и `./gradlew build` для аддона) и
возвращает только первые N ошибок с `файл:строка`, без полного лога. Сейчас агент гоняет их вручную и получает
большие выводы.
