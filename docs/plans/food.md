# План: раздел «Еда» — сборные блюда

Статус: **сделано**. Во вкладке «Еда» три вида: «Продукты» (плоская таблица по `data/*/tfc/food`),
«Сборные блюда» (`?tab=food&sub=meals`) и «Готовые блюда» (`?tab=food&sub=dishes`).

## Сделано

- `scripts/mods/meals.mjs` → `public/meals.json`.
- Семейства из рецептов с модификатором `tfc:meal` (16 семейств, 26 блюд): основа, слоты начинок с количеством
  «от и до» по всем вариантам рецепта, инструмент, значения самого блюда и доли от ингредиентов. Блюда, отличающиеся
  только видом основы (шесть хлебов), сливаются в одно семейство.
- Формула `tfc:meal` (проверено по `MealModifier.apply`): значения блюда + по каждому ингредиенту-еде
  `его значение × множитель доли × количество`; долю выбирает первый подходящий `ingredient`, доля без него — для
  всех остальных. Сытость и порча — всегда из блюда. Значения множителей по умолчанию (1) — из кодека `MealPortion`.
- Суп (`SoupPotRecipe`) и салат (`SaladContainer`) — из кода: класс, создающий еду с вычисленной питательностью
  (`setFoodForDynamicItemOnCreate` + `new FoodData`), коэффициент, вода и насыщение блюда, число порций супа.
- «Дальше»: рецепты с `copy_dynamic_food` (сырая пицца → пицца из печи).
- Состав тегов начинок — на сайте из `tags.json` с правками KubeJS; поиск по продукту находит блюда, куда он годится.
- Ботаника: на карточке растения в «Куда идёт» — ссылки на блюда, куда годится плод (`mealsByItem`: слоты блюд +
  состав тегов начинок); ссылка открывает «Сборные блюда» с поиском по этому продукту (`&q=`). Только сам плод:
  зерно в блюда не идёт, а хлеб из него — основа, её не считаем.
- Калькулятор на каждой карточке (`calcMeal`, `calcComputed` в `src/lib/meals.ts`): выбор основы и продуктов из
  состава тегов, питательность продуктов — из справочника еды; у супа — число порций и значения на порцию, у супа и
  салата — какой именно предмет получится. Одноимённые продукты разных модов подписаны модом.
- Kaleidoscope (мод совместимости `ktfcc`): «блюдо без рецепта» в воке и в кастрюле. Если набор продуктов не подошёл
  ни под один рецепт посуды, а все продукты входят в тег (`ktfcc:pot_ingredient` / `stockpot_ingredient`), еда
  считается формулой. Скрипт читает её из байткода: аргументы `new FoodData(…)` в подмешанном классе, помощники
  (`getFinalNutrients` — сумма, обнуление самой малой группы, множитель, предел; `calculateDecayModifier`), настройки
  `dynamicNutrientMultiplier` и `maxDynamicNutrient` (значения по умолчанию — из класса конфига, действующие — из
  `ktfcc-common.toml` в Firestore), вместимость посуды (9) — из класса посуды в jar Kaleidoscope, id тегов — из
  инициализации полей класса тегов. На сайте — карточка с формулой и калькулятор (`calcDynamic`).
- Farmer's Delight: по коду `farmerstfc` еда нигде не вычисляется — у блюд постоянная питательность из
  `data/farmersdelight/tfc/food`. Сборные из них только те, что сделаны через `tfc:meal` (гамбургер, салаты, шашлык) —
  они уже в семействах.
- Cuisine Delight (`scripts/mods/cuisine.mjs` → `meals.json`, раздел `skillet`): блюдо со сковороды на тарелке.
  Продукты и их время — данные `cuisinedelight_config/ingredient` всех модов; оценка готовки —
  `CookedFoodData.of` (100 × (1 − Σ вес × штраф / Σ вес), ниже 60 — несъедобно); питательность TFC — подмена выдачи
  тарелкой в `cuisinetfc` (`PlateItemMixin`): сумма по продуктам (для части — запись «в жареном виде»
  `cuisinetfc/cooked_food`), самая малая группа обнуляется, × оценка / 100 / `foodSize`, не больше `maxNutrient`,
  у `suspicious_mix` ещё × `suspiciousMixFactor`; вода (фрукты + овощи) × 5, насыщение 0,8 за продукт, порча
  max × 0,8, сытость 4, порций в блюде `foodSize`. Название блюда — рецепты `cuisinedelight:plate_cuisine` (доли
  по весу; на питательность влияет только `suspicious_mix`). Подмена стоит только на `useOn` (тарелкой по стоящей
  сковороде): со сковороды в руке блюдо выходит без питательности TFC — скрипт определяет это по классу аддона.
  Настройки — `cuisinetfc-common.toml` и `cuisinedelight-server.toml` (вместимость) в Firestore. На сайте — карточка
  `SkilletCard` с продуктами, названиями блюд и калькулятором (`calcSkillet`: продукт, штук, как приготовлен).
  KubeJS сборки меняет только `transform/other.json` (вид продукта на сковороде), на расчёт не влияет.
- Вонючий суп Firmalife (`StinkySoupRecipe`, тип `firmalife:stinky_soup`): 3–4 продукта для супа + паслён; вода 20
  и насыщение 2 у блюда, всё × (1 − 0,05 × число продуктов), на порции **не делится** (каждая из `floor(n/2)+1`
  порций получает всё), сытость 4, порча 3,5, предмет один. Скрипт читает это как «блюдо одного вида» (`singleDish`).
- Салат: за раз собирается столько, сколько штук в наименьшей стопке среди продуктов и мисок (до 64), хватит одного
  продукта — из `SaladContainer.setAndUpdateSlots` (счётчик стопки и условие «продуктов > 0»).
- Калькулятор блюд из рецептов сверяет набор с настоящими вариантами рецепта (`combos` в семействе): у бутерброда
  с вареньем — варенье **или** заготовка и не больше двух начинок.
- Джемы (`tfc:pot_jam`) и `firmalife:bowl_pot` — не сборные: у всех джемов одна постоянная питательность (еда
  `tfc:preserves`), у пасты она записана в рецепте. Их место — вид «блюда по посуде».
- KubeJS текущей сборки ни один из 577 рецептов блюд не удаляет (проверено `recipeFilter.ts`), поэтому отсев
  удалённых пока не встроен.

- «Готовые блюда» (`?tab=food&sub=dishes`, `DishesTab`): еда с постоянной питательностью по способу приготовления
  (тип рецепта) — кастрюли TFC и Farmer's Delight, вок, пароварка, джемы, печь, нагрев и т. д. Строится на сайте из
  каталога рецептов (`recipes.json` + `kubejs.json`), поэтому показывает только работающие в игре рецепты; блюда
  с `tfc:meal` туда не входят. Питательность — из справочника еды, а если рецепт задаёт её сам (`firmalife:bowl_pot`,
  поле `food`) — из рецепта. Название способа — предмет с тем же id, что и тип рецепта, если он есть.
- Отсев удалённого KubeJS: «Сборные блюда» скрывают блюда, варианты супа и названия блюд сковороды, чьи рецепты
  удалены скриптами или отключены заглушкой (`hasStatus(r, 'active')`), и пишут, сколько скрыто.
- Связи: в «Продуктах» столбец «В блюда» (в сколько сборных блюд годится продукт, ссылка открывает их поиском);
  на карточке семейства — ссылки на рецепты каждого блюда; раздел рецептов принимает фильтры из адреса
  (`/recipes?item=<id>[&usage=1][&type=<тип>][&q=…]`).
- Датапак сборки (`kubejs/data`): `scripts/kubejs.mjs` пишет `public/kubejs-data.json` — еду (`tfc/food`), продукты
  сковороды (`cuisinedelight_config/ingredient`) и «жареную» питательность; сайт заменяет ими записи модов с тем же
  файлом (`loadReference`, `loadMeals`). Сейчас сборка так задаёт еду торта и овощной файл сковороды. Для прочих
  данных, которые сайт читает только из модов, `npm run kubejs` выводит предупреждение.

## Осталось

Раздел закрыт. Сознательно не сделано:

- Блюда `tfc:meal`, добавленные скриптами KubeJS (не датапаком), в «Сборные блюда» не попадут: `meals.json` собирается
  из jar. Сейчас таких нет.
- Сковорода: эффекты зелий у продуктов (`effects`) и опыт за блюдо не показаны; при равном счёте двух рецептов
  название блюда не определить (в коде — первый по порядку загрузки).
- Еда из `kubejs/data`, заданная тегом, а не предметом: состав тега на сайте не раскрывается (скрипт предупредит).

## Что такое сборное блюдо

Рецепт, в который ингредиенты подставляются через тег: сэндвич = любой хлеб + любые начинки, суп = любые овощи,
салат, пицца, джем, блюда Farmer's Delight и Kaleidoscope. Один такой рецепт «использует» почти всю еду сборки:
у арахиса в ботанике было 156 рецептов, из них свой продукт — три.

Как отличить скриптом (уже применяется в `scripts/mods/botany.mjs`): предмет на выходе считается сборным, если он
получается из пяти и более разных растений. Для раздела еды нужен более точный признак — см. ниже.

## Что показывать

| Блок | Содержимое | Откуда |
| --- | --- | --- |
| Семейство блюда | «Сэндвич», «Суп», «Салат», «Пицца», «Джем»… | группировка рецептов по типу и общему шаблону id (`*_bread_sandwich`, `*_soup`) |
| Основа | все варианты хлеба (ячменный, кукурузный, овсяный, рисовый, ржаной, пшеничный) | вход рецепта, заданный тегом основы |
| Начинки | что можно класть и сколько слотов | теги ингредиентов рецепта (`#tfc:foods/usable_in_sandwich` и подобные) + состав тегов из `public/tags.json` |
| Что получится | сытость и питательные группы зависят от начинок | модификаторы результата в рецепте (`tfc:meal`, `copy_food` и т. п.) — разобрать формулу в коде |
| Посуда и способ | миска, кастрюля, нож, печь | тип рецепта и требуемые предметы |

## Что разобрать

1. Типы рецептов сборных блюд в каталоге (`public/recipes.json`): какие поля задают основу, начинки, число слотов.
2. Формулу питательности результата: модификаторы `ItemStackModifier` у TFC (класс `MealModifier` и соседние) —
   через `scripts/mods/classfile.mjs`, как в ботанике.
3. Составы тегов начинок — уже есть в `public/tags.json`; учесть правки KubeJS.
4. Блюда других модов (Farmer's Delight, Kaleidoscope Cookery, Firmalife): у них свои типы рецептов и своя еда,
   часть рецептов сборка удаляет скриптами — показывать только живые.

## Связи с другими разделами

- Ботаника: в «Куда идёт» вместо числа «сборные блюда: N» — ссылки на семейства («идёт в сэндвичи, супы»).
- Рецепты: фильтр по семейству.
- Справочник еды: у продукта — «в какие сборные блюда годится».
