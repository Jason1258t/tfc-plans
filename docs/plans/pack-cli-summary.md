# Итоги: программа `tfc` и сервер сборки (на 2026-10-20)

Сводка по плану [pack-cli.md](pack-cli.md) после работы 2026-10-20: что уже работает, что проверено, что нет,
и что ждёт решения хоста. Подробности — в самом плане, `cli/README.md`, `server/pack-server/README.md`, `docs/STATE.md`.

## Что сделано

| Этап | Что это даёт | Состояние |
| --- | --- | --- |
| 1. Разборщики как библиотека | `npm run pack -- <папка версии>` — все данные сайта одной командой из папки игры | готово |
| 2. Сервер сборки | хранит сборку версиями (снимками), раздаёт по ключам, откат на прошлую | готово, стоит на VPS |
| 3. Программа `tfc` | игроку: `init`, `login`, `status`, `sync` (моды, конфиги, KubeJS, ресурспаки, с копиями и `--undo`); хосту: `publish`, `admin` | готово |
| 4. Сборка данных на сервере | сервер сам собирает предметы/рецепты/карту из залитой сборки и выкладывает на сайт только изменённое | готово, **выкладка только пробная** |
| 5. Сайт для `tfc pull` | «Ставить в мир» у датапаков, скрипты KubeJS на сайте, общие модули датапака и схем | готово (2026-10-20): `tfc pull` — датапаки, скрипты, схемы |
| 6. Один файл | `tfc` для Windows / macOS / Linux, скачивание на странице «Обновления» | готово |
| MCP сборки | агенту — быстрые ответы по предметам, рецептам, тегам, гайдам, jar | готово, локально |

### Что это значит для игроков

Сейчас — **пока ничего**: на сервере сборки нет текущей сборки, ключей игрокам не выдано. Как только хост зальёт
сборку и раздаст ключи, игрок скачивает `tfc` со страницы «Обновления», делает `tfc init`, `tfc login <ключ>`,
`tfc sync` — и получает моды, конфиги, KubeJS и ресурспаки сборки. Свои моды игрока (миникарта, шейдеры) не трогаются,
изменённые им конфиги не затираются (кладётся `*.tfc-new`), перед заменой — копия, `tfc sync --undo` возвращает.
Схемы, отмеченные датапаки и скрипты KubeJS с сайта ставит `tfc pull` (после обновления кода на сервере сборки).

### Что это значит для хоста

- `tfc publish` с ПК, где стоит игра, — заливает сборку (только новые файлы) и делает её текущей для всех.
- Сервер после этого сам собирает данные сайта и показывает, что изменилось бы на сайте. Настоящая выкладка —
  отдельной командой (ниже), пока не включена автоматически.
- Деплой сайта с машины без jar может брать данные модов с сервера (`TFC_PACK_URL`/`TFC_PACK_TOKEN` в `.env.local`).

## Как проверено

- **Сервер сборки** — локально node-скриптами (заливка, снимки, откат, отказы по ключам и путям, перезапуск) и на VPS:
  тестовая сборка (jar и KubeJS с Mac) залита и собрана, данные совпали с сайтом в 7564 из 7566 файлов
  (разница — метка времени и подпись двух серверных скриптов KubeJS).
- **Программа** — node-скриптом на искусственных папках (Prism-хост, игрок со своими модами, папка сервера):
  58 сверок, включая обрыв загрузки; собранный файл для macOS (arm64 и x64) — 33 сверки хост+игрок.
- **Выкладка на сайт** — только на имитации Hosting. Пробный прогон на VPS: изменился бы один файл, `kubejs.json`.
- **Сверено при подведении итогов (только чтение):**
  - VPS: службы `tfc-pack` и `caddy` работают, `/health` снаружи отвечает; снимок один, **текущего нет**;
    два задания сборки, оба с пробной публикацией; ключи — только `host` и `claude` (оба admin), ключей игроков нет;
    `AUTO_PUBLISH` в настройках не задан — значит пробный режим. Диск 11 из 30 ГБ, памяти свободно ~1,0 ГБ, свопа нет.
  - Hosting: все выкладки сайта сделаны с ПК разработчика (`firebase deploy`), с сервера — ни одной.
  - Firestore: 7 датапаков — **ни один не отмечен «Ставить в мир»**; скриптов KubeJS на сайте — 0; схем — 4.

## Что не проверено

- **Windows** — exe не запускался вообще (проверен только заголовок файла). Блокировка jar запущенной игрой — по коду.
- **Linux-файл** — тоже не запускался.
- **Настоящий лаунчер** — на Mac инстансов нет; `tfc init` на настоящей папке Prism/CurseForge хоста не проверялся.
- **Настоящая сборка хоста** — `tfc publish` и `npm run pack` на ней ни разу не запускались.
- **Выкладка с сервера на сайт** и запись в Firestore сервисным ключом — ни разу.
- **Игра** — что после `tfc sync` клиент запускается и заходит на сервер, не проверялось.
- Успешная запись гайда через MCP (`guide_put`) — не делалась, проверены только отказы.

## Что нужно от хоста — по приоритету

### 1. Залить настоящую сборку (`tfc publish`)

Без этого игрокам нечего синхронизировать. На ПК с игрой (Windows):

```bash
tfc init --instance "<клиентская папка игры>" --world "<мир>" --server-dir "<папка сервера>"
tfc login tfc_…            # ключ администратора host, выдан при установке
tfc status                 # что будет залито
tfc publish --note "первая сборка"
```

- Сборка сразу станет **текущей** — её получат все по `tfc sync`. Сначала залить, не делая текущей:
  `tfc publish --no-current`, проверить, потом `tfc admin use <id>`.
- Если на папке не определилась версия игры, `publish` падает с «mc — строка до 40 символов» — добавить
  `--mc 1.21.1 --loader neoforge` (известная мелочь, не исправлена).
- **Скрипты KubeJS сервера** (`steel_heated.js`, `ee_heater_crucible.js`) должны попасть в `kubejs/server_scripts`
  заливаемой папки: сервер сборки видит только залитое, иначе сайт потеряет эти рецепты.
- Это первый реальный запуск на Windows — если что-то упадёт, пришлите вывод целиком.

### 2. Разрешить первую выкладку с сервера на сайт

После шага 1 сервер сам соберёт данные и сделает пробный прогон. Посмотреть, что изменится, и выложить:

```bash
curl -s -H "Authorization: Bearer tfc_…" https://tfc-pack.duckdns.org:28788/jobs
curl -s -X POST -H "Authorization: Bearer tfc_…" -H "Content-Type: application/json" -d '{"dryRun":false}' https://tfc-pack.duckdns.org:28788/admin/publish
```

Команды в `tfc` для этого нет (`tfc admin rebuild` / `publish` — не сделаны), поэтому `curl` или попросить агента.
Это первая запись сервисным ключом: обновятся данные сайта, конфиги в Firestore и запись в «Обновлениях».
Включать ли потом автоматическую выкладку (`AUTO_PUBLISH=live` в `/etc/tfc-pack.env`) — решить после первой.

### 3. Выдать ключи игрокам

```bash
tfc admin invite <ник>     # ключ показывается один раз — передать игроку лично
tfc admin keys             # список; отозвать — tfc admin revoke <id>
```

Игрокам — ссылка на страницу «Обновления» (скачать `tfc`) и три команды оттуда. Первым лучше дать одному игроку
на Windows и попросить прислать вывод `tfc init` и `tfc sync`.

### 4. Отметить датапаки «Ставить в мир»

Сейчас отмечен один из 8 («Фикс магмы»). На сайте: Датапаки → датапак → «Ставить в мир» для тех, что должны стоять на сервере
(например, проверенные в игре `electroenergetics_missing`, `pellet_arc_furnace`). Отмеченные ставит
`tfc pull datapacks`. Тестовые не отмечать.

### 5. Удалить сервисный ключ Firebase из «Загрузок»

На Mac лежит `~/Downloads/tfc-plans-fd2c-firebase-adminsdk-fbsvc-*.json` — полный доступ к базе и хостингу.
Копия уже на сервере (`/etc/tfc-pack/firebase-sa.json`). Удалить из «Загрузок» и очистить корзину; если ключ
куда-то пересылался — отозвать его в консоли Firebase (Настройки проекта → Сервисные аккаунты) и выпустить новый.

### 6. Своп на VPS — на всякий случай

Сборка занимает ~0,8 ГБ, свободно ~1,0 ГБ (рядом Xray и прокси Telegram). Сейчас хватает, но запас маленький:
вырастет сборка или чужая служба — сборку убьёт нехватка памяти (в задании так и будет написано). Своп-файл на 2 ГБ
другие службы не трогает; на диске место есть. На VPS (`ssh tfc`):

```bash
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile && echo '/swapfile none swap sw 0 0' >> /etc/fstab
```

### 7. Мелочи

- Ключ `claude` (admin) на сервере — для проверок агентом; не нужен — `tfc admin revoke <id>`.
- Проверить на Windows хотя бы `tfc --version` и `tfc init` — до раздачи игрокам.

## Что осталось сделать в коде

По важности для игроков:

1. ~~**`tfc pull`**~~ — сделано 2026-10-20 (раздел `/site` сервера сборки + команда).
2. **`tfc admin rebuild` / `publish` / `jobs`** — пересборка и выкладка из программы, без `curl`.
3. **`tfc publish` без `--mc`** — не падать, а спрашивать или брать версию из папки.
4. **Слой KubeJS сервера** отдельно от клиентского (сейчас — класть серверные скрипты в `kubejs/` снимка).
5. **`tfc fetch`, `tfc config set`** — сборка с сервера на рабочую машину, правка конфига без ПК хоста
   (`npm run pack:fetch` уже есть).
6. **Чистка на сервере** — старые `data/<снимок>/`, неиспользуемые файлы; пока место не жмёт.
7. **MCP на сервере** — чтобы агенту не нужна была копия сборки на ПК.
8. Потом: `tfc update` (самообновление), подпись exe для Windows/macOS, `tfc ui`, ошибки из `latest.log`.
