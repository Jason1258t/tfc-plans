# План: разбор директории сборки целиком

Статус: **не начато**, только план. Сейчас источники разбираются четырьмя отдельными командами, и каждый приходит
отдельным архивом от хоста. Цель — одна команда на всю папку сервера и понятный способ эту папку доставить.

## Что есть сейчас

| Источник в папке сборки | Команда | Куда попадает | Что берём |
| --- | --- | --- | --- |
| `mods/*.jar` | `npm run mods` | `public/*.json`, `public/icons/` | предметы, рецепты, теги, справочник, ботаника, география, настройки по умолчанию |
| `config/`, `serverconfig/` | `npm run serverconfig -- <zip>` | Firestore `config` (слои `config`, `server`) | только используемые `*-server.toml` / `*-common.toml` |
| `kubejs/` | `npm run kubejs -- <zip>` | `public/kubejs.json`, `kubejs-items.json`, `icons-kubejs/` | скрипты, датапак `kubejs/data`, свои предметы и их иконки |
| `<мир>/data/` | `npm run world -- <файл>` | Firestore `config` (слой `world`) | календарь TFC |

## Чего не хватает

1. **Одной точки входа.** `npm run pack -- <папка сборки | zip>` должен сам найти внутри `mods/`, `config/`,
   `serverconfig/`, `kubejs/`, папку мира и запустить нужные части. Отдельные команды остаются.
2. **Доставки.** Сервер — ПК хоста (Windows), сайт собирается на другой машине. Варианты, от простого:
   - скрипт на стороне хоста (`tools/export-pack.ps1`): собирает один zip только из нужного — см. «Что класть в архив»;
   - общая папка/облако с этим zip;
   - сборка сайта прямо на ПК хоста (нужны Node и `firebase login`) — тогда архив не нужен вовсе.
3. **Снимка источников.** Файл `instance/sources.json`: что импортировано, откуда, когда, sha1. По нему видно, что
   устарело, и можно печатать «конфиг новее импортированного» вместо молчаливого расхождения.
4. **Остального содержимого папки**, которое сейчас не читается вовсе (ниже).

## Что класть в архив от хоста

Обязательно: `config/` (без `fancymenu`, `jmsharedmaps`, `CSC`, `voicechat`, `xaero`, `*.bak`), `serverconfig/`, `kubejs/`
(с `assets`), `<мир>/data/tfc_calendar.dat`, `<мир>/datapacks/`, `logs/latest.log`.
При обновлении сборки — ещё `mods/`. Никогда: `server.properties`, списки игроков, `playerdata/`, `stats/`, `region/`.

## Порядок работ

1. `npm run pack` поверх существующих частей + `instance/sources.json` (малая).
2. `tools/export-pack.ps1` для хоста с белым списком путей (малая; проверить на Windows может только хост).
3. `<мир>/datapacks/` → пометка на странице датапака «установлен на сервере / отличается» (средняя).
4. `logs/latest.log` → список ошибок загрузки рецептов, тегов и скриптов KubeJS, привязанный к датапакам сайта (средняя).
5. `config/ftbquests/` → раздел «Квесты» (средняя).
6. `level.dat` → сид и правила игры (малая).
7. Слой открытой карты из регионов или JourneyMap (большая, отдельный план).

## Правила, которые не меняются

- Всё, что показывает сайт, достаётся скриптом из файлов сборки; руками ничего не вписывается.
- Коллекцию `config` читает любой посетитель: туда идёт только используемое и только без секретов и личного.
- Скрипты делятся по источнику (папке), а не по разделу сайта.
