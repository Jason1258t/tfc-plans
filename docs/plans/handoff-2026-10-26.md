## Правила работы (проверены практикой)

- Одна ветка — одна страница. Ворктри: `git worktree add .claude/worktrees/<имя> -b refactor/<имя> main`,
  потом `npm ci` внутри (симлинк `node_modules` ломает шрифты), дев-сервер на своём порту (5204+).
- **Снимки**: `npm run ui:shots -- capture before --url http://localhost:<порт> --only <страница>` → поменял код →
  `capture after` → `diff before after`. Цель — «Отличий нет». Живые данные дают 0,01–0,8% (счётчики, «7 дн. назад») —
  смотри вырезанный фрагмент, а не цифру.
- В ворктри нет `public/*.json` и `public/icons*` — скопируй из основной копии перед съёмкой (они в `.gitignore`,
  коммитить нельзя). `preview`-сборка на localhost не грузит Firestore — для проверки бери дев-сервер.
- У страницы `/schematics` нет `<main>` — `waitFor: "main"` для неё не сработает.
- **Ловушка каскада**: `Button.module.css` и `Field.module.css` лежат **без `@layer`** и попадают в отдельный
  CSS-чанк, поэтому `.foo :global(.btn)` / `:global(.input)` перестают работать. Переопределения пиши локальным
  классом или элементным селектором (`.foo select`, `.foo > input`) — они выигрывают по специфичности, а не по
  порядку чанков.
- `size="sm"` не забывай: потерянный размер даёт 34 px вместо 28 и сдвиг панели — снимки это ловят.
- `Button` — один вариант за раз: `btn ghost danger` → `<Button variant="ghost" className={styles.dangerGhost}>`
  с локальным красным ghost (так уже сделано в задачах и схемах).
- Ничего не писать в Firestore/`dev_*` без надобности; отчёт — в задаче «Разработки» (`dev_update status=done
report=…`) и в `docs/state/site.md`.
- Перед слиянием: `npx tsc -b`, `npx oxlint src scripts`, `npm run ui:classes -- --check`,
  `npm run ui:boundaries`, `npx prettier --write` по своим файлам. Слияние — `ship` (мержит, деплоит, пушит).
