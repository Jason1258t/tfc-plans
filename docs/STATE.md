## Что работает (задеплоено)

- **Структура сайта** (переработана 2026-10-13). В шапке: Задачи · Документы (файловое хранилище) · Схемы · Датапаки · Справочник, справа —
  колокольчик обновлений сборки. Markdown-планы (бывшие «Документы») — раздел «Планы» страницы задач (`/?view=docs`, слева над группами). Датапаки,
  рецепты и теги — один раздел с выбором вкладки слева (адреса `/datapacks`, `/recipes`, `/tags` прежние). Карта —
  вкладка справочника (`/reference?tab=map`). Документ на всю страницу — `/doc/{id}` (старые `/docs/{id}` и `/map?x=…` перенаправляются).
- **Документы** — страница файлов (`/docs`, на месте прежней страницы документов; `/files` ведёт туда же): всё хранилище одним списком — поиск по имени, автору, задаче и схеме, фильтр по виду,
  загрузка файла без привязки, скачивание, удаление (исходники библиотеки схем отсюда не удаляются).
- **Задачи**: список, важность, Elo-сравнение, группы, чеклист ресурсов, вложения и галерея, место на карте.
- **Планы** (Markdown-документы) с предметами и агентом Gemini; чекбоксы `- [ ]` отмечаются кликом в режиме просмотра (и в плане, и в описании задачи).
- **Схемы Create (.nbt)**: замена блоков вручную / правилами / агентом, удаление блока из схемы, проверка id по
  библиотеке, импорт материалов схемы в чеклист задачи, общая **библиотека схем** (исходник + замены + форма).
  Форма при скачивании: обрезка по крайним блокам, отступы (бока/низ/верх), «очистить пространство» = явный воздух
  во всех свободных клетках (не для схем с несколькими палитрами, до 2 млн клеток). В игре не проверялось.
- **Датапаки**: шаблон / замена / удаление рецептов, произвольные файлы, zip, «К задаче», проверки (устаревший исходник,
  нет предметов, **«KubeJS удалит»**), выгрузка датапака KubeJS-скриптом.
- **Рецепты** (отдельная страница): весь каталог без лимита, статусы с учётом KubeJS, **конструктор** обхода удалений.
- **Теги** (отдельная страница): состав по модам и KubeJS, поиск по id и по содержимому, редактор правки датапаком
  (дополнить / убрать / заменить). Формат `remove` не проверялся по коду NeoForge, в игре не проверялся.
- **Ботаника** (вкладка справочника, боковое меню: культуры / кусты / деревья): климатические диапазоны, плоды и
  семена, фильтр по T и влажности; из кода модов — расход N/P/K, тип культуры, календарь сезонов по месяцам, рост
  саженца, срок созревания (множитель роста — из конфига сервера), длина месяца из сохранения мира, урожай культур
  из loot-таблиц, где растение встречается в природе, плодов за сбор, серверные сроки саженцев, календарь в часах
  игры, свет и почвы, куда идёт урожай (без сборных блюд), гибель перестоявшей культуры. Подвкладка «Теплица»
  (Firmalife): 63 растения, грядка, материал стен по уровню, удобрения. Виноград: сезоны, скорость роста и условия качества урожая из кода. Срок созревания в теплице. Карточка переработана: полоски диапазонов, блоки удобрений, календарь с подписями месяцев.
  Разбор `.class` — `scripts/mods/classfile.mjs`. Что осталось — `docs/plans/botany.md`.
- **Справочник**: вкладки Руды · Топливо · Металлы · Еда · Ботаника · Карта. Топливо — одна вкладка с подразделами слева: твёрдое (без дерева) и жидкое с нефтью (`?tab=fuel&sub=liquid`; старый `tab=liquid` ведёт туда же).
- **Карта мира** TFC Real World: проекция из мода, обычный вид и слои, клик — координаты, города, расстояния,
  спавн; параметры мира — из импортированного конфига сервера.
- **Обновления сборки**: запись при деплое + патчноут от модели.
- **Сборщики**: `npm run mods`, `npm run serverconfig`, `npm run kubejs`, `pack-release` при деплое.
- Пакет **firestore-files@0.1.0** (отдельный репозиторий пользователя) — на нём вложения и исходники схем.

## Отложено по решению пользователя

- Логика фильтров атрибутов (сломана в самой проверке, не лечится конфигом) — «пока опустим».
- Поиск «уголь рядом с X» с точками на карте — «пока без такого функционала».
- Реальная карта мира с зумом до города и слой открытой в игре карты (нужен мини-мод или экспорт) — обсуждали «в вакууме».

## Известные ограничения

- KubeJS: составы тегов неизвестны (фильтр по предмету не видит рецепты, где предмет задан тегом); у рецептов из
  хелперов модов (`event.recipes.create.mixing(...)`) нет полного JSON. Свои предметы сборки (`kubejs:*`, `tfcr:*`, 25 шт.)
  в библиотеке есть, но русские названия только у 8 — остальных нет в `kubejs/assets/*/lang/ru_ru.json`.
- Библиотека — предметы, а не блоки: в схемах цель замены не проверяется на «это вообще блок».
- Починенный предохранитель из датапака получает ток срабатывания по умолчанию.
- Совместное редактирование документа: побеждает последняя запись.
- README, раздел «Структура» — краткий; подробная карта кода в `CLAUDE.md`.

## Куда проект движется (обсуждали, не начато)

Пользователь думает выложить проект сообществу, чтобы сайт разворачивали у себя без доработок:

- **Рабочие области**: одна область = свой снимок сборки, конфиг генерации, карта, задачи, схемы, датапаки
  (`workspaces/{id}/…`). Сейчас всё в плоских коллекциях и синглтонах (`settings/world`, `config/server__…`).
- **Снимок сборки как артефакт**, а не часть билда; сборщики — независимые шаги с общим входом «папка инстанса».
- **Хранение тяжёлого** (иконки, карты, тайлы) — главный вопрос: Firestore не подходит, нужна статика/внешнее хранилище.
- **Модули по модам**: парсер объявляет нужные моды, интерфейс прячет вкладку без данных.
- Попутное правило уже сейчас: не плодить новые синглтоны; у `config` есть `scope` — задел под область.

План в `docs/plans/` для этого ещё не написан — предлагалось оформить `docs/plans/community.md`.
