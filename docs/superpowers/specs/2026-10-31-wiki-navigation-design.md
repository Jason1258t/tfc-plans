# Навигация TFC Studio в стиле игровой вики

Дата: 2026-10-31  
Dev-задача: #179  
Статус: пилот реализован и проверен; целевая структура ожидает подтверждения

## Цель и границы

Сделать TFC Studio понятной точкой входа для игрока: с главной можно перейти к задачам группы, игровой справке и инструментам, а справочник организован по игровым смыслам, а не по десяти равнозначным техническим вкладкам.

Сохраняются спокойная тема #178, медные активные состояния, зелёная семантика положительных статусов и весь 3D-редактор. Не меняются игровые данные, статьи, состав гайдов, компоненты просмотра контента и рабочие операции.

## Карта текущего состояния

| Адрес                             | Содержимое и параметры                                                                                                   |
| --------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| `/`                               | Задачи и планы. `?task=`, `?doc=`, `?view=docs\|people`, `?group=`, `?tab=done`, `?who=`                                 |
| `/docs`                           | Файловое хранилище; `/files` — старый адрес                                                                              |
| `/doc/:id`                        | Документ на всю страницу; `/docs/:id` — старый адрес                                                                     |
| `/schematics`                     | Библиотека и редактор схем; `?id=` открывает запись                                                                      |
| `/builder`                        | Конструктор построек; `?from=` открывает схему                                                                           |
| `/datapacks`, `/recipes`, `/tags` | Общий раздел с боковым выбором; сохраняются `pack`, `script`, `q`, `item`, `type`, `kind`, `tag`                         |
| `/reference`                      | Руды по умолчанию; `tab=ores\|geology\|fuel\|metals\|food\|botany\|power\|multiblocks\|guides\|map`                      |
| `/reference?…`                    | Дополнительно `sub`, `g`, `mb`, `rock`, `q`, координаты карты; старые `tab=liquid`, `tab=addons`, `tab=power&sub=guides` |
| `/addons`, `/addons/:id`          | Список, страница аддона; `?sub=guides&g=` для статей разработчиков                                                       |
| `/map`                            | Старый адрес карты; координаты переносятся в `/reference?tab=map`                                                        |
| `/updates`, `/freshness`          | Лента обновлений и свежесть модов                                                                                        |
| `/dev`                            | Разработка; `task`, `report`, `section` и другие параметры                                                               |
| `/stats`                          | Скрытая статистика, в меню не появляется                                                                                 |

В шапке сейчас: «Задачи», «Документы», «Схемы», «Датапаки», «Справочник», «Аддоны», «Разработка». Поиск в шапке ищет только id предмета и вызывается по Ctrl/Cmd+K. Внутри справочника поиск относится к открытой вкладке.

## Подходы

1. **Смысловые категории поверх существующих страниц, канонические ссылки и редиректы — выбран.** Позволяет менять информационную архитектуру небольшими проверяемыми частями, не переписывая вкладки и не разрывая ссылки.
2. Полный переход на вложенные пути `/reference/world/ores`, `/guides/power/...`. Структура красивее в адресной строке, но требует одновременно переписать много ссылок и повышает риск ошибок. Возможен позже, но не нужен для цели.
3. Только добавить меню или выпадающий список. Дешевле, но не решает ни главную, ни дублирование гайдов, ни сценарии возврата; не подходит.

## Предлагаемая целевая структура

### Главная `/`

Не рекламная страница, а каталог возможностей:

- короткий заголовок и одно предложение о назначении TFC Studio;
- поиск по названиям, описаниям и ключевым словам разделов;
- плитки «Справочник», «Гайды», «Карта мира», «Аддоны»;
- плитки «Задачи», «Схемы Create», «Датапаки», «Документы»;
- спокойные вторичные ссылки на конструктор построек, обновления и разработку.

Поиск на главной фильтрует навигационный указатель и не претендует на полнотекстовый поиск по статьям. Поиск id предмета в шапке остаётся самостоятельным инструментом.

### Справочник `/reference`

Предлагаются шесть непустых смысловых разделов:

| Раздел                     | Содержимое                                                                      |
| -------------------------- | ------------------------------------------------------------------------------- |
| «Мир и ресурсы»            | Руды, геология, карта мира                                                      |
| «Переработка и рецепты»    | Металлы, твёрдое и жидкое топливо, полный каталог рецептов                      |
| «Еда и сельское хозяйство» | Продукты, сборные и готовые блюда; культуры, кусты, деревья, растения и теплица |
| «Электричество»            | Существующие справочные подразделы и переход к профильным гайдам                |
| «Мультиблоки»              | Структуры, материалы, слои и переход к профильным гайдам                        |
| «Предметы и теги»          | Поиск предметов и их id, состав тегов и связи между ними                        |

Рецепты, предметы и теги относятся к справочной информации, а не к редактору датапаков. Существующие компоненты `/recipes` и `/tags` переиспользуются внутри справочника, их прежние адреса и query-параметры сохраняются совместимыми переходами. Внутренние вкладки и поведение других страниц не перестраиваются.

Отдельная пустая категория «Техника» в справочнике не создаётся: машины и добыча раскрываются в гайдах, а схемы и конструктор остаются рабочими инструментами. Так игровой смысл не смешивается с файловыми операциями.

Старые значения `tab` остаются допустимыми и канонизируются редиректами с сохранением остальных параметров.

### Гайды

Гайды остаются внутри справочника на `/reference?tab=guides…`; отдельный верхнеуровневый раздел не создаётся. Предлагаемые категории:

- «Электричество» — существующий раздел `power`;
- «Машины и добыча» — существующий раздел `multiblocks`, включая IE, Advanced TFC Tech и Create Ore Excavation;
- «TFC Studio» — существующий раздел `site`.

«Аддоны» не дублируются в общем списке гайдов: статьи для разработчиков остаются в `/addons?sub=guides`, ссылка на них доступна из каталога гайдов. Идентификаторы статей, содержимое и права редактирования не меняются.

## Пилот

В пилот входят только:

1. Новая главная `/` с плитками и локальным поиском по разделам.
2. Задачи на `/tasks`; любой старый `/?…` перенаправляется на `/tasks?…` без потери query.
3. «Мир и ресурсы» на `/reference?tab=world` с подразделами `sub=ores|geology|map`.
4. Старые `tab=ores`, `tab=geology`, `tab=map`, `?rock=` и `/map?…` ведут в новый раздел с сохранением фильтров и координат.
5. Внутренние новые ссылки на задачи используют `/tasks?…`, но старые адреса продолжают работать.

Остальные вкладки справочника, гайды, аддоны и весь контент остаются прежними до подтверждения пилота.

## Основные сценарии

1. **Новый игрок ищет, где найти руду.** Главная → «Справочник» → «Мир и ресурсы» → «Руды». Переход из «Геологии» сохраняет фильтр `rock`.
2. **Игроку прислали координаты.** Старый `/map?x=…&z=…` или новый адрес карты открывает ту же точку; ссылки на задачи с карты ведут на `/tasks?task=…`.
3. **Игрок возвращается к задаче по старой ссылке.** `/?task=<id>` открывает `/tasks?task=<id>` и то же окно.
4. **Игрок ищет инструмент.** Вводит на главной «схемы», «рецепты» или «карта» и переходит по результату; Enter открывает первый результат, Tab проходит по ссылкам.
5. **Возврат назад.** Плитки и подразделы используют обычную навигацию браузера. Редиректы старых адресов используют `replace`, поэтому кнопка «Назад» не зацикливается.
6. **Прямая ссылка на гайд, аддон или встроенный материал.** Адрес и `g`, `mb`, `id` сохраняются; редирект меняет только расположение навигации.

## Desktop, mobile и клавиатура

- Шапка сохраняет текущую модель: горизонтальная прокрутка основных разделов на узком экране, компактный логотип, доступный поиск id предмета.
- Плитки главной: три колонки на широком экране, две на промежуточном, одна на телефоне. Область нажатия — вся карточка.
- В «Мире и ресурсах» на desktop подразделы слева, на mobile — переносимой строкой сверху, как в существующем `SectionShell`.
- Активный раздел обозначается текстом и `aria-current`/`aria-pressed`, а не только цветом.
- Поле поиска имеет видимую подпись для скринридера, понятный placeholder и сообщение об отсутствии результатов.
- Все карточки — настоящие ссылки: доступны Tab, Enter, «Открыть в новой вкладке» и контекстное меню браузера.
- Фокус использует существующий `--focus`, без новых свечений.

## Дизайн-спецификация

- Максимальная ширина главной и обычного справочника — 1080 px; карта сохраняет широкий режим 1400 px.
- У главной отступы 32 px сверху, 56 px снизу и 16 px по бокам; на телефоне верхний отступ — 24 px, боковые 16 px сохраняются.
- Плитки используют `--surface`, радиус `--radius`, без тени. При hover/focus появляется функциональный контур `--border-strong` и спокойный `--surface-2`.
- Иконки плиток — существующие Lucide, нейтрального текста; медь только у активных и акцентных элементов. Новых цветов и цветных градиентов нет.
- Заголовок главной до 28 px, заголовки групп 13–14 px, описания плиток 13 px; плотность не уменьшается за счёт мелкого текста.
- Содержимое вкладок, таблицы, игровые иконки, карта и 3D не перекрашиваются.

## Проверка

Пилот: desktop/mobile, light/dark, главная, поиск с клавиатуры, `/tasks`, руды, геология, карта, активные состояния, «Назад», старые root/reference/map ссылки и отсутствие горизонтального переполнения.

Полная версия после подтверждения: остальные категории справочника, рецепты, предметы и теги внутри него, упрощение категорий гайдов без отдельного верхнеуровневого раздела, все старые ссылки и query-параметры, встроенные материалы, аддоны и карта. Обязательные проверки: Prettier изменённых файлов, `npm run lint`, `npx tsc -b`, `npm run boundaries`, `npm run ui:boundaries`, production build и браузерная матрица desktop/mobile × light/dark.

## Критерий пилота

Игрок с главной за один переход понимает, где задачи, схемы, датапаки и игровая справка; руды, геология и карта воспринимаются как один раздел; старые ссылки открывают прежний контент. После показа пилота полная перекомпоновка начинается только с подтверждения пользователя.
