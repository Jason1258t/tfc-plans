# Сервер сборки

Сервер, который хранит сборку игры и раздаёт её программе [`tfc`](tfc-app.md). Он же сам собирает из сборки данные
сайта (предметы, рецепты, карту, разбор KubeJS) и выкладывает их на сайт. Пересобрать данные и обновить сайт можно
с любого устройства, ПК с Minecraft для этого не нужен.

- Код — [server/pack-server/](../server/pack-server/). Полная справка (установка с нуля, все настройки, API) —
  [server/pack-server/README.md](../server/pack-server/README.md).
- Зачем так устроено и порядок работ — [plans/pack-cli.md](plans/pack-cli.md). Что сделано и что ждёт решения —
  [plans/pack-cli-summary.md](plans/pack-cli-summary.md).

## Как это работает

- **Снимок** — версия сборки. Это список файлов (путь, контрольная сумма, размер), а сами файлы хранятся по
  одному разу. Поэтому одинаковый jar в десяти версиях занимает место один раз, а обновление сборки — десятки МБ.
- **Текущий снимок** — то, что получают игроки по `tfc pull`. Откат — переключение на прошлый снимок, ничего
  не удаляется.
- **Ключи.** Моды раздаются только своим, поэтому без ключа сервер отвечает только на `/health`.
  - Роль `player` — качать сборку.
  - Роль `admin` — заливать, переключать, выдавать ключи, публиковать на сайт.
  - На сервере хранится только хеш ключа: ключ показывается один раз при выдаче.
- **Белый список путей.** В снимок принимаются:
  - `mods/`, `config/`, `defaultconfigs/`, `serverconfig/`, `kubejs/`, `resourcepacks/`;
  - из мира — `datapacks/` и календарь TFC.

  Никогда не принимаются `server.properties`, списки игроков (ops, whitelist, баны), данные игроков, регионы мира
  и логи (в логах — адреса игроков). Снимок с таким путём отклоняется целиком.

### Что происходит после `tfc publish`

1. Программа хоста заливает только те файлы, которых на сервере ещё нет, и создаёт снимок.
2. Снимок становится текущим, и игроки получают его по `tfc pull`.
3. Сервер ставит в очередь задание **сборки данных сайта**. Оно идёт отдельным процессом, по одному за раз.
4. Затем **публикация**: сервер сравнивает собранное с тем, что сейчас на сайте.
   - **С 2026-10-22 она живая** (`AUTO_PUBLISH=live`): сервер сначала подтягивает свежий код сборки, собирает
     данные и сразу выкладывает их на сайт. Откат сборки (`tfc admin rollback`) тоже сразу уходит на сайт.
   - Посмотреть заранее, что изменится, — `tfc admin publish` (без `--live`, пробно).
   - Выкладывается только изменённое: файлы данных на Hosting, настройки сборки в Firestore `config`
     и запись в «Обновления сборки», если поменялись моды, предметы или рецепты.
   - Сам сайт, аддоны и ресурспаки остаются такими, как их выложил разработчик.
   - **Данные сборки на сайт ставит только сервер.** Деплой сайта с ПК (`npm run deploy:site`) их не трогает:
     берёт из текущего релиза как есть.
   - **Защита.** Объёмные иконки предметов сервер рисует сам. Если сборка их почему-то не нарисовала, прежние на
     сайте остаются. Если с сайта убралось бы больше 300 файлов, настоящая публикация останавливается — проверьте
     список и, если всё верно, `tfc admin publish --live --allow-removals`.

Ход заданий — `tfc admin jobs`, подробнее — в [инструкции программы](tfc-app.md#хосту).

### Шум: что не заливается

Игра и моды переписывают часть файлов при каждом запуске, не меняя настроек. Из-за этого почти каждая заливка
«меняла» одни и те же ~10 файлов. По истории снимков (5 заливок 20–21.10.2026) из 28 изменений настоящих было 2
(`worldborder.json5`, `submarine_hull.json`). Теперь `tfc publish` их отсекает:

| Что                                  | Пример                                                                                                                                                                                                                            | Что делает `tfc`                                                             |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| Состояние модов, кеши, личное        | `emi-accelerator/reload-timings.json`, `*.emic`, `jei/world/…`, `spark/activity.json` (ник и UUID), `sodium-fingerprint.json` (отпечаток ПК), `chunky/tasks/`, `create_submarine_client_state.json`, `NCR-ServerPreferences.json` | не заливает; у игрока не ставит и не убирает                                 |
| Дата в шапке `.properties`           | `#Wed Oct 21 19:39:53 MSK 2026` в `iris.properties`, `packetfixer.properties`                                                                                                                                                     | сравнивает без неё                                                           |
| Пустые строки, пробелы в конце, CRLF | `coldsweat_altitude-server.toml` растёт на 8–24 пустые строки за запуск                                                                                                                                                           | сравнивает без них                                                           |
| Клиентские настройки                 | `*-client.snbt` (`ftbchunks-client.snbt` перемешивает порядок), `-client`/`_client` в имени                                                                                                                                       | версию на сервере не обновляет: у игроков они всё равно только добавляются   |
| Время мира в календаре TFC           | `calendarTime`, `playerTime` в `tfc_calendar.dat`                                                                                                                                                                                 | сравнивает без них; длина месяца (`daysInMonth`) — настройка, она заливается |

Если файл отличается от версии на сервере только этим, в новый снимок идёт версия сервера, и `publish` пишет, какие
файлы так оставил. Правила — `server/pack-server/lib/paths.mjs` (`isStatePath`, `isClientConfig`, общие с сервером)
и `cli/lib/noise.mjs` (сравнение по смыслу). Новый «шумный» файл — смотреть историю снимков:
`/var/lib/tfc-pack/snapshots/*.json` и `blobs/<sha256>` (файлы, которые меняются почти в каждом снимке).

У игрока: если игра переписала только дату или пустые строки, `tfc pull` обновляет файл, а не кладёт `*.tfc-new`;
если игрок поменял конфиг, а в сборке этот файл с прошлого `pull` не менялся, — оставляет правку молча.

### Задачи разработки

С 2026-10-26 задачи разработки (бывшие группы «Разработка» и «Фиксы») и журнал работ агентов хранятся здесь, а не
в Firestore: журнал агентов съедал бесплатный лимит чтений. Страница сайта — «Разработка» (`/dev`), агентам — MCP
`tfc-plans-dev` (`dev_*`). План — [plans/dev-tracker.md](plans/dev-tracker.md).

- База — один файл `/var/lib/tfc-pack/dev.db` (встроенный в Node SQLite, без пакетов и отдельной службы).
- Бэкап — сам сервер раз в сутки кладёт копию в `/var/lib/tfc-pack/dev-backup/`, хранит 14 последних.
- Доступ: ключ сервера сборки любой роли (агенты, программа `tfc`) или вход сайта (анонимный вход Firebase,
  с App Check, если задан `APP_CHECK_PROJECT_NUMBER`) — тот же уровень, что у правил Firestore. Подпись — ник.
- Сайт обращается сюда из браузера: адреса сайта разрешены в `DEV_ORIGINS` (по умолчанию — сайт и localhost).
- Перенос старых задач — `node scripts/dev-migrate.mjs` (пробно), `--import`, после проверки — `--delete`.

### Что ещё раздаёт сервер

- **Собранные данные снимка** (`/data`). Отсюда их берёт `npm run dev` (адрес и ключ — `TFC_PACK_URL` и
  `TFC_PACK_TOKEN` в `.env.local` или вход в программу `tfc`) и `npm run pack:fetch -- --data`. Jar снимка
  `npm run pack:fetch` кладёт в кеш вне репозитория (`~/.cache/tfc-plans/pack`) — для MCP, `npm run mods` и аддонов.
- **Версии аддонов** (`/site/addons`, ключ игрока): карточки `tools/*/addon.json` из копии репозитория + версии из
  Firestore `addonVersions`; jar каждой версии — обычный файл хранилища по sha256 (`/blobs/<sha256>`). Заливает
  `tfc admin addon upload <jar>` (ключ администратора): файл, затем `POST /admin/addons` — сервер заводит версию
  на сайте черновиком; другой jar под той же версией не принимает. Без ключа игрокам доступны только текущие версии
  со статики сайта.
- **Отчёты игроков** (`POST /site/reports`, ключ игрока): `tfc report` присылает лог или краш-репорт (пачку — zip),
  сервер кладёт его в хранилище файлов сайта (Firestore `files`, частями по 700 КБ, автор — имя ключа). На сайте —
  «Разработка» → «Краш-репорты»/«Логи», агенту — MCP `report_get`.
- **Контент сайта для `tfc pull`** (`/site/…`): датапаки с отметкой «Ставить в мир», скрипты KubeJS с отметкой
  «Ставить на сервер», библиотека схем.
  - Сам сайт закрыт App Check, поэтому программа берёт этот контент здесь, а сервер читает Firestore своим
    сервисным ключом.
  - Списки кешируются на 5 минут, чтобы не тратить бесплатный лимит чтений.

### Чужие службы на машине — не трогать

На VPS уже работают другие службы, и они важнее нашей:

- прокси Telegram (Docker) на 443;
- Xray на 6080, 6443, 6444 и 8080; порт 8443 зарезервирован под Xray;
- бот;
- raven-subscribe на 47291;
- правило ufw на 6000.

Поэтому HTTPS сервера сборки — не на 443, а на 28788, и порт 80 не открывается: сертификат выдаётся через DNS.

Прежде чем открывать новый порт, проверьте его:

- `ss -tulnp` — кто что слушает;
- `ufw status`;
- `iptables -t nat -S`;
- конфиг Xray;
- `history` пользователя root.

### Обновления сборки от Claude

Claude (ключ `claude-agent`) не заливает сборку сам: он выкладывает **предложенное обновление** — несколько файлов
и пути, которые убрать (`tfc admin propose`). Оно лежит в `/var/lib/tfc-pack/updates/` и игрокам не раздаётся.
Хост забирает его к себе (`tfc admin updates pull`), проверяет в игре и одобряет (`tfc admin updates approve`) —
тогда сервер делает новый снимок из текущего с этими файлами. Одобрить может только другой администратор, не автор.
Подробно — [инструкция программы](tfc-app.md#хосту).

### Обслуживание

```bash
ssh tfc 'systemctl status tfc-pack caddy --no-pager'   # работают ли
ssh tfc 'journalctl -u tfc-pack -n 100 --no-pager'     # лог: каждая заливка, снимок, ключ — строка с именем ключа
ssh tfc 'df -h / && free -m'                           # место и память
```

**Обновить код сервера** после слияния в `main`:

```bash
ssh tfc 'cd /opt/tfc-plans && git pull && bash server/pack-server/deploy/install.sh'
```

- Без домена в аргументах скрипт только обновляет код и перезапускает службу. Настройки, сборку и ключи он
  не трогает.
- Код разборщиков для сборки данных сайта — отдельная копия репозитория в `/var/lib/tfc-pack/repo`.
  Её подтягивает `tfc admin rebuild --pull`.

**Ключи** удобнее выдавать из программы: `tfc admin invite <ник>`, `tfc admin keys`, `tfc admin revoke <id>`.
Без программы — прямо на сервере (`node cli.mjs key …` в `/opt/tfc-pack`, см.
[README сервера](../server/pack-server/README.md#ключи)). Последний ключ администратора отозвать нельзя.

**Бэкап** — копия папки `/var/lib/tfc-pack`. Сейчас он не настроен.

**Настройки** (`/etc/tfc-pack.env`) после правки применяются через `systemctl restart tfc-pack`. Главные:

| Настройка                        | Что значит                                                                          | Сейчас                     |
| -------------------------------- | ----------------------------------------------------------------------------------- | -------------------------- |
| `AUTO_BUILD`                     | собирать ли данные сайта после смены текущего снимка                                | не задана (`on`)           |
| `AUTO_PUBLISH`                   | после сборки: `dry-run` — только показать, `live` — сразу выложить, `none` — ничего | `live` (с 2026-10-22)      |
| `BUILD_HEAP_MB`                  | лимит памяти процесса сборки                                                        | 640 (сборка берёт ~0,9 ГБ) |
| `GOOGLE_APPLICATION_CREDENTIALS` | сервисный ключ Firebase для публикации и `/site`                                    | задан                      |

### Память

Сборка данных модов берёт до ~0,9 ГБ при свободных ~1,0 ГБ, а свопа на машине нет. Если сборку убьёт нехватка
памяти, в задании так и будет написано. Тогда нужен своп (около 2 ГБ на диске). Создавать его — только с согласия
хоста: машина общая.

## Запустить у себя для разработки

```bash
cd server/pack-server
npm run key -- add host --role admin   # ключ администратора в ./data/keys.json
npm run dev                            # http://127.0.0.1:8788, данные — ./data
```

Программа к нему: `tfc login <ключ> --server http://127.0.0.1:8788`. Сборку данных такой сервер запускает из этого
же репозитория. Пробная публикация читает Firebase от имени `firebase login`.
