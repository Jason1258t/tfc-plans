# tfc — сборка TFC RealWorld на вашем ПК

Программа сверяет папку игры со сборкой на сервере и докачивает недостающее: моды, конфиги, скрипты KubeJS,
ресурспаки. Хост с её помощью заливает новую версию сборки. Устройство и планы — [docs/plans/pack-cli.md](../docs/plans/pack-cli.md).

## Установить

Три способа, выберите один. На сайте, раздел «Обновления» (https://tfc-plans-fd2c.web.app/updates), блок
«Программа tfc» показывает то же самое для вашей системы, с кнопкой «Копировать».

**1. Одной командой (проще всего).** Скачает программу, сверит контрольную сумму, поставит в свою папку
(Windows — `%LOCALAPPDATA%\Programs\tfc`, macOS и Linux — `~/.local/bin`) и пропишет её в PATH. Права администратора
не нужны.

- **Windows** — в PowerShell (Win + X → «Терминал»):

  ```powershell
  irm https://tfc-plans-fd2c.web.app/tfc/install.ps1 | iex
  ```

- **macOS, Linux** — в Терминале:

  ```bash
  curl -fsSL https://tfc-plans-fd2c.web.app/tfc/install.sh | sh
  ```

**2. Скачать файл.** Один файл, Node.js не нужен:

| Система            | Файл                                                                  |
| ------------------ | --------------------------------------------------------------------- |
| Windows            | https://tfc-plans-fd2c.web.app/tfc/tfc-win-x64.zip (внутри `tfc.exe`) |
| macOS, Apple M1–M4 | https://tfc-plans-fd2c.web.app/tfc/tfc-macos-arm64.zip                |
| macOS, Intel       | https://tfc-plans-fd2c.web.app/tfc/tfc-macos-x64.zip                  |
| Linux              | https://tfc-plans-fd2c.web.app/tfc/tfc-linux-x64.zip                  |

- **Windows:** распакуйте и запустите `tfc.exe` двойным кликом — программа предложит поставить себя, Enter. Если
  Windows пишет «защитила ваш компьютер» — «Подробнее» → «Выполнить в любом случае»: у файла нет платной подписи.
- **macOS:** в Терминале `xattr -d com.apple.quarantine ~/Downloads/tfc` (снять метку «скачано из интернета», файл
  без подписи Apple), потом `~/Downloads/tfc install`.
- **Linux:** `chmod +x ~/Downloads/tfc`, потом `~/Downloads/tfc install`.

`tfc install` можно и не делать: тогда команды пишутся из папки с файлом — `.\tfc.exe …` (Windows) или `./tfc …`.

**3. Через npm** — если уже стоит Node.js 20 или новее. Пакет меньше мегабайта:

```bash
npm install -g https://tfc-plans-fd2c.web.app/tfc/tfc.tgz
```

После установки **откройте новое окно терминала** — в нём команды пишутся просто `tfc …`. Убрать программу —
`tfc uninstall` (настройки и ключ останутся; для npm — `npm uninstall -g tfc-plans`).

Версия — `tfc --version`. Раз в сутки программа сама смотрит на сайте, нет ли новой, и подсказывает. Обновить —
`tfc --upgrade`: файл скачается, сверится, пробно запустится и только потом заменит старый (пакет npm обновит сам npm).
Настройки и ключ при обновлении сохраняются.
`tfc --upgrade` появился в версии после 2026.10.20-540e283 — с неё и более ранних обновиться один раз вручную.

Из папки проекта (нужен Node.js 22+) — как раньше: `npm run tfc -- <команда>` или `npm link` → `tfc <команда>`.

## Игроку: первый раз

1. Ключ попросите у хоста сборки (он делает его командой `tfc admin invite <ваш ник>`).
2. Укажите папку игры и мир:

   ```bash
   tfc init
   ```

   Программа сама ищет версии в Prism Launcher, MultiMC, CurseForge, Modrinth и ATLauncher и предлагает выбрать.
   Нужной нет в списке — введите путь к папке, где лежит `mods/`. Можно и сразу: `tfc init --instance <папка> --world <мир>`.

   Сборки ещё нет — `tfc init --launcher`: поставит NeoForge, версию TFC-RealWorld в `.minecraft/versions/` (её папка —
   папка игры; видна и в TLauncher) и профиль «TFC RealWorld» в официальный Minecraft Launcher и скачает сборку (спросит ключ и память; `--memory 6`,
   `--mc-dir`, `--name`). Лаунчер перед этим запустить хотя бы раз и закрыть; Java 21 берётся та, что скачал лаунчер.

3. Войдите ключом:

   ```bash
   tfc login tfc_…
   ```

## Игроку: обновить сборку

```bash
tfc status   # что изменится — ничего не трогает
tfc pull     # докачать и обновить всё (спросит подтверждение)
```

Перед `pull` закройте игру. Одна команда берёт всё, что нужно этой папке:

- **сборку с сервера сборки** — моды, конфиги, KubeJS, ресурспаки (с выбранным миром — и его датапаки);
- **аддоны сборки** с сайта (вкладка «Аддоны») — папке сервера только серверные и общие;
- **с сайта** — скрипты KubeJS с отметкой «Ставить на сервер», датапаки с отметкой «Ставить в мир» (если выбран мир),
  библиотеку схем (на клиенте).

Что программа делает и чего не делает:

- **Удаляет только то, что ставила сама** и чего больше нет в сборке или с чего на сайте сняли отметку. Ваши моды
  (миникарта, шейдеры) не трогает, а только показывает в `status`. Исключение — старая версия мода из сборки или
  аддона под другим именем файла: с двумя jar одного мода игра не запустится, поэтому старый убирается (с копией).
- **Ваши правки не затирает.** Если вы меняли конфиг или скрипт после прошлого `pull`, новая версия ляжет рядом
  с именем `*.tfc-new`. Сравните и оставьте нужное. Перезаписать всё равно: `tfc pull --force`.
- **Клиентские конфиги** (`*-client.toml`: интерфейс, клавиши модов) только добавляются, если их нет. Ваши не меняются.
- **Всё заменённое и убранное сохраняется** в `<папка игры>/.tfc/backup/`. Вернуть как было до последнего `pull`:
  `tfc undo` (последние 5 раз).
- Оборванная загрузка продолжится с места обрыва. Каждый файл сверяется по контрольной сумме.
- `--dry-run` — только показать, `--yes` — не спрашивать (без терминала замены и удаления — только с `--yes`).

**Только часть:** `tfc pull mods`, `tfc pull config kubejs`. Части:

| Часть           | Из сборки                                     | С сайта                     |
| --------------- | --------------------------------------------- | --------------------------- |
| `mods`          | моды                                          | аддоны                      |
| `config`        | `config/`, `defaultconfigs/`, `serverconfig/` | —                           |
| `kubejs`        | `kubejs/`                                     | скрипты «Ставить на сервер» |
| `resourcepacks` | ресурспаки                                    | —                           |
| `datapacks`     | датапаки мира                                 | датапаки «Ставить в мир»    |
| `world`         | календарь мира                                | —                           |
| `schematics`    | —                                             | библиотека схем             |
| `addons`        | —                                             | аддоны                      |

**Одно названное с сайта** (сборку не трогает):

```bash
tfc pull datapacks zinc       # датапак по имени — любой, и тестовый (для проверки в одиночном мире)
tfc pull schematics Дом       # одна схема по названию
tfc pull addons rw-host-fix   # один аддон (имя — id или имя jar: rw_host_fix, rw-host-fix-1.0.0.jar)
```

Имена с пробелами — в кавычках: `tfc pull datapacks "Фикс магмы"`. Общий `pull` уберёт датапак, поставленный
по имени, если на нём нет отметки.

**Сборка и сайт не спорят за файл:**

- **У аддонов главный сайт.** Если в сборке лежит другая версия того же аддона, её программа не ставит. Файлы сборки,
  которые аддон заменяет (у `rw-host-fix` — `kubejs/server_scripts/event/eratosthenes_portal_clamp.js`), тоже
  не ставятся, а если уже стоят — уходят в копию. Это помнится и при `tfc pull kubejs` без аддонов. Ключ для аддонов
  не нужен: они берутся прямо с сайта (`/addons/index.json` и jar), без ключа `tfc pull addons` тоже работает.
- **У датапаков сайта главный сайт.** Они ставятся как `<мир>/datapacks/tfc-plans-<id>.zip` и в сборку не
  заливаются: `tfc publish` пропускает и их, и копии, скачанные с сайта кнопкой «Скачать» (`Фикс_магмы.zip`), если
  датапак отмечен «Ставить в мир». Такую ручную копию рядом с поставленной `tfc pull` убирает (с копией в
  `.tfc/backup/`): с двумя версиями одного датапака в мире правка на сайте не доходила бы до игры. Если датапак
  сайта уже лежит в сборке (заливали раньше), `pull` берёт его с сайта, а не из сборки. Свои датапаки хоста,
  которых нет на сайте, идут через сборку, как раньше.
- **У скриптов главная сборка.** Если хост уже залил скрипт сайта в сборку, он приходит из сборки, а сайт этот путь не
  трогает.
- Ваш файл с тем же именем, что у файла с сайта (например, свой `kubejs/server_scripts/fix.js`), не затирается:
  версия с сайта ляжет рядом как `*.tfc-new`. Перезаписать: `--force`.

Хосту: аддоны и отмеченное на сайте игроки получают сразу, перезаливать сборку не нужно. `tfc publish` после `pull`
нужен, чтобы сервер сборки пересобрал данные сайта (рецепты, предметы) с новыми аддонами и скриптами.

Раньше команда называлась `tfc sync` (и `tfc sync --undo`) — старое имя пока работает и подсказывает новое.

Несколько папок игры — несколько профилей: `tfc init --profile тест`, переключение — `tfc use тест`,
разово — `--profile тест`.

## Хосту

Ключ администратора выдаётся при установке сервера сборки (`server/pack-server/README.md`).

```bash
tfc init --instance <клиентская папка игры> --world <мир>   # откуда заливать
tfc login tfc_…                                             # ключ администратора
tfc status                                                  # чем ваша папка отличается от сборки на сервере
tfc publish --note "обновил Create до 6.0.4"                # залить
```

- Заливаются только файлы, которых на сервере ещё нет: обновление сборки — десятки МБ, а не вся сборка.
- Берётся белый список: `mods/*.jar`, `config/` (без `xaero`, `voicechat`, `fancymenu`, `jmsharedmaps`, `CSC`,
  `*.bak`), `defaultconfigs/`, `serverconfig/`, `kubejs/` (без `exported`, `probe`), `resourcepacks/`, из мира —
  `datapacks/` и `data/tfc_calendar.dat`. Никогда не берутся `options.txt`, `server.properties`, списки и данные
  игроков, регионы мира, логи.
- Заливать лучше из **клиентской** папки: игрокам нужны и клиентские моды. Серверный `serverconfig/` можно взять
  из папки сервера: `tfc init --server-dir <папка сервера>`.
- Если сборку на сервере меняли с другого устройства (например, конфиг с ноутбука), `publish` не затрёт это молча:
  покажет файлы и попросит сначала забрать их (`tfc pull config`) или залить поверх (`--force`).
- `tfc build` собирает данные сайта из папки игры локально в `./tfc-out` (как `npm run pack`, без записи
  в Firestore), чтобы посмотреть до заливки. Работает только из папки проекта, в одном файле её нет.

На папке сервера (где `server.properties`) `tfc pull` по умолчанию не трогает моды сборки: в сборке хоста есть
клиентские моды, серверу они не нужны. Аддоны (серверные и общие) ставит. Моды сборки на сервер — явно:
`tfc pull mods`. Конфиги, `serverconfig/`, KubeJS и датапаки мира — как обычно.

| Команда                           | Что делает                                                           |
| --------------------------------- | -------------------------------------------------------------------- |
| `tfc admin invite <ник>`          | ключ игрока (`--admin` — администратора); ключ показывается один раз |
| `tfc admin keys` / `revoke <id>`  | список ключей / отозвать                                             |
| `tfc admin history`               | версии сборки                                                        |
| `tfc admin rollback` / `use <id>` | откатить на прошлую / сделать текущей конкретную                     |

### Данные сайта с сервера сборки

После `tfc publish` сервер сам собирает данные сайта (предметы, рецепты, карта, разбор KubeJS) и **пробно**
сравнивает их с сайтом. На сайт они попадают только по вашей команде:

```bash
tfc admin jobs                      # задания сервера: что собиралось, получилось ли
tfc admin jobs last                 # последнее подробно: конец лога и что изменилось бы на сайте
tfc admin publish                   # ещё раз сравнить с сайтом (пробно)
tfc admin publish --live            # выложить на сайт — спросит подтверждение
```

- `tfc admin rebuild [mods,kubejs,config,world]` — пересобрать данные текущей сборки (все части или только
  указанные). `--pull` — сервер сначала подтянет свежий код сайта (после правки разборщиков). `--publish` — что
  делать после сборки: `dry-run` (по умолчанию — только показать), `none`, `live` (сразу выложить, с вопросом).
- Команды сборки и публикации ждут конца задания и показывают лог; Ctrl+C — перестать смотреть, задание на
  сервере продолжится (`--no-follow` — не смотреть сразу). Потом: `tfc admin jobs <id> --follow`.
- Итог публикации: сколько файлов сайта новых/изменённых/убрать, какие настройки сборки запишутся в базу, будет ли
  запись в «Обновлениях сборки» (если поменялись моды, предметы или рецепты).
- Выложить можно только **текущую** сборку; другую сначала сделать текущей (`tfc admin use <id>`). Без терминала
  (в скрипте) подтверждение — `--live --yes`. `--snapshot <id>` — пробная сборка или сравнение другого снимка.

### Правки конфигов от Claude

```bash
tfc admin changes                   # предложенные правки: зачем, ключи, было → станет
tfc admin changes pull [id…]        # внести в config/ папки игры и сервера (покажет и спросит; --dry-run, --yes)
tfc admin changes reject <id>       # отклонить
```

Claude предлагает их через MCP (`config_propose`), файлы сам не трогает. Правится только значение ключа, прежние
файлы — в копию (`tfc undo`), итог по каждому ключу уходит обратно (Claude видит его в `config_changes`). Потом —
перезапуск сервера, `tfc publish` и `tfc admin publish --live`.

- Версию игры `publish` берёт из папки лаунчера, иначе — из прошлой сборки на сервере, иначе спрашивает.
  Задать явно: `tfc publish --mc 1.21.1 --loader neoforge`.

## Где что лежит

- Настройки и ключ: `~/.config/tfc/config.json` (Windows: `%APPDATA%\tfc\config.json`). Файл с ключом читает
  только владелец.
- В папке игры: `.tfc/state.json` (что ставила программа: из сборки — `files`, с сайта — `pulled`, файлы сборки,
  которые заменяют аддоны, — `addonOverrides`),
  `.tfc/site-files/` (исходники схем с сайта), `.tfc/hashes.json` (кеш контрольных сумм),
  `.tfc/backup/` (копии).
- Скачанные файлы сборки — общий кеш: macOS `~/Library/Caches/tfc`, Windows `%LOCALAPPDATA%\tfc\cache`, Linux
  `~/.cache/tfc` (там же установщик NeoForge для `tfc init --launcher` и его лог).

## Собрать файлы для игроков (разработчику)

```bash
npm run tfc:dist                       # все системы → dist-tfc/ и public/tfc/
npm run tfc:dist -- --only macos-arm64 --no-public   # одну, не трогая public/
```

- esbuild собирает `cli/tfc.mjs` в один скрипт (разборщики `scripts/` в него не попадают — сборка это проверяет;
  из сайта попадают только общие модули `src/lib/datapackFiles.ts`, `schematicFile.ts`, `nbt.ts` и fflate),
  Node SEA вшивает его в официальный Node той же версии, что запускает сборку (блоб привязан к версии Node).
  Node для всех систем качается с nodejs.org, хеш сверяется с `SHASUMS256.txt`, кеш — `.cache/node-dist/`.
- Файлы macOS подписываются своей подписью (`codesign -s -`) — без неё Apple Silicon файл не запустит; собирать
  поэтому на Mac. Windows-файл без подписи.
- Версия — дата и хеш последнего коммита, менявшего `cli/` (или эти общие модули): пересборка без правок программы не заставит игроков
  обновляться. Незакоммиченные правки — версия с `-dirty`.
- `public/tfc/` (zip и `version.json`) в git не хранится и уходит на сайт обычным деплоем (`npm run deploy:site`).
  Проверка обновлений читает `https://tfc-plans-fd2c.web.app/tfc/version.json` (`TFC_UPDATE_URL` — другой адрес,
  `TFC_NO_UPDATE_CHECK=1` — выключить).
- Почему сайт, а не сервер сборки: скачать программу нужно до того, как у игрока есть ключ, а все запросы сервера
  сборки — с ключом; сайт уже раздаёт статику (ресурспаки), а сервер сборки и так нагружен сборкой. Лимит трафика
  бесплатного Firebase Hosting — 360 МБ в сутки, файл — 33–41 МБ в zip: для группы хватает, для большой раздачи —
  перенести на сервер сборки.
