# TFC Real World: Host Fix (`rw_host_fix`)

Миксин-аддон для TFC Real World 4.1.4 + TFC Eratosthenes 4.0.0. Две правки.

## 1. Хост меняет измерение — карта «ломается» для всех

**Что было.** В «мире хоста» (одиночный мир, открытый для сети) после того, как хост проходил в ад, умирал или
телепортировался в другое измерение, всех игроков в обычном мире каждый тик переносило к одной точке
(Z ≈ −20 100), а новые чанки генерировались океаном. Помогал только перезаход хоста.

**Почему (по байткоду и логам игры 2026-10-21).**
- `TFCRealWorld.onLevelUnload` при выгрузке *клиентского* мира вызывает `TFCRealWorldConfig.clearServerConfig()`.
  Настройки — статические поля; у хоста клиент и встроенный сервер в одной программе, поэтому стирались и
  серверные: карта откатывалась к значениям по умолчанию 80 000 × 40 000 вместо 200 000 × 100 000.
- Eratosthenes (`OverworldClimateModelMixin`) при следующем построении климата берёт размер из этих настроек
  («Half meridian set to 20000» в логе), считает базу (Z = −37 133) «за северным полюсом» и каждый тик
  (`PlayerEventHandler.northPolarPushback`) ставит игроков на Z = −20 000 − polarAreaSize.
- Генерация (Eratosthenes `limitWorldGenerationOutsideMapProjection`) за «краем» новой карты — океан
  («canceled land at point» в логе).
- При запуске мира `ConfigManager.onServerAboutToStart` читает настройки заново — поэтому помогал перезаход.

**Исправление.** `mixin/TFCRealWorldConfigMixin`: пока в программе работает сервер
(`ServerLifecycleHooks.getCurrentServer() != null`), `clearServerConfig` ничего не делает. При запуске мира сервер
читает настройки заново, при входе на чужой сервер тот присылает свои (`ConfigSyncPacket`). У гостя и на выделенном
сервере поведение не меняется.

Миксин — на класс настроек, а не на `TFCRealWorld`: тот ссылается на классы клиента, и переписанный миксином класс
на выделенном сервере не загружается («Attempted to load class net/minecraft/client/Minecraft for invalid dist» при
пересчёте фреймов) — так упала первая версия на сервере разработки.

## 2. Выход из ада за край карты

Заменяет скрипт KubeJS `server_scripts/event/eratosthenes_portal_clamp.js` из чужой сборки (его нужно удалить):
у него граница ±19 500 (под мир 40 000 блоков), из-за чего выход из ада около нашей базы уводил в Сахару, а перенос
командой `/tp` снова вызывал тот же переход — скрипт вызывал сам себя, и выйти из ада было нельзя даже командой.

`NetherPortalClamp`: только переход через портал ада в обычный мир (команды и другие измерения не трогает); если
точка выхода (×8) дальше края карты минус 1000 блоков (размеры — из настроек TFC Real World), переход отменяется и
на следующем шаге сервера игрок переносится к краю карты на поверхность.

Ограничение: точку портала по ту сторону Minecraft ищет (и грузит чанки) до этого события — отменить это нельзя.

## Сборка и проверка

- `./build.sh` — jar без Gradle: компиляция против Minecraft+NeoForge из среды `../ee-rectifier-mod`
  и TFC Real World из `mods/`.
- `./test-server.sh` — сервер разработки (`devserver/`, NeoForge 21.1.251, как у хоста) с TFC, Patchouli,
  TFC Real World и аддоном; проверочный мод — команда `/rwtest`:
  `mixin` (применился ли миксин, какой размер карты видит сервер), `clear` (стирание настроек при работающем сервере), `portal <x> <z>` и `command <x> <z>`
  (переход тестового игрока без клиента из ада).

Что проверено и что нет — на странице аддона на сайте (`/addons/rw_host_fix`).

Новая версия TFC Real World (зависимость `[4.1.4,4.2)`): сначала проверить, не исправил ли автор `onLevelUnload` сам.
