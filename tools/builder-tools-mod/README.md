# Builder Tools — инструменты строителя

Аддон для Minecraft 1.21.1 / NeoForge 21.1.251+, Curios 9+. Устанавливается на сервер и всем игрокам.
Версия 1.0.1, dev-задача №103.

## Пояс строителя

Наденьте `builder_tools:builder_belt` в слот Curios «Пояс». Пояс в обычном инвентаре не действует.
Shift + ПКМ с поясом в руке включает или выключает его; состояние сохраняется на предмете.

- При размещении последнего блока в основной или второй руке подставляет стопку таких же блоков из 36 обычных
  слотов инвентаря. Сравниваются все компоненты: названия, данные и варианты не смешиваются. Занятая рука не
  заменяется; основная рука не становится источником для пополнения второй. Содержимое рюкзаков не просматривается.
- При первом ударе и удержании ЛКМ по блоку переносит подходящий инструмент в активный слот. Предыдущий предмет
  занимает его место; это работает и с полным инвентарём. На блоках с требованием инструмента сначала учитывается
  возможность получить дроп, затем базовая скорость добычи. Уже подходящий инструмент заменяется только на лучший.
  Чары эффективности отдельно не оцениваются. Инструменты с одним оставшимся применением не выбираются автоматически.
- Наведение, ПКМ и удары по существам инструмент не меняют. При открытом меню или занятом курсоре обмена нет.
  Творческий и наблюдательный режимы не используют пояс. Обратного переключения после отпускания ЛКМ нет.

Рецепт: `LLL / LJL`, где L — кожа (`minecraft:leather`), J — джутовое волокно (`tfc:jute_fiber`).
Рецепт загружается при наличии TFC; сам аддон требует только Curios и NeoForge.

## Реализация и проверка API

По MCP проверен код Minecraft/NeoForge 21.1.251:

- `Minecraft.startAttack` и `continueAttack`: событие `InputEvent.InteractionKeyMappingTriggered` перед началом и
  продолжением добычи. Обработчик ограничен клиентом; использует стандартный `ClickType.SWAP` через меню инвентаря,
  пакет обмена отправляется раньше пакета начала добычи. Собственного сетевого протокола и миксинов нет.
- `CommonHooks.onPlaceItemIntoWorld`: расход и откат предмета после проверки размещения. До взаимодействия сохраняется
  исходная стопка; в `PlayerTickEvent.Post` перенос возможен лишь когда она действительно опустела и рука свободна.
- `ItemStack`: `getDestroySpeed`, `isCorrectToolForDrops`, компонент `TOOL`; учитываются реальные правила блока и
  инструмента, включая инструменты TFC. Слоты Curios запрашиваются без кеша по предмету на весь тик.

Кожа и джутовое волокно проверены MCP `recipes_for` по сборке: доступны через обработку шкур и вымачивание джута.

## Сборка и проверки

```bash
./libs.sh
JAVA_HOME=$HOME/.gradle/local-tools/jdk21/Contents/Home ./gradlew build
./test-server.sh
TFC=1 ./test-server.sh
TFC=1 ./test-client.sh
./release.sh
```

Проверочный мод `src/devtest` не попадает в выпускной jar. Сервер использует отдельные порты 25615 / 25715
(переопределяются `PORT`). Клиент сам создаёт временный плоский мир и закрывается после проверки.

- Сервер NeoForge + Curios: 23 проверки — ношение и отключение, тип/уровень инструмента, износ, обмен при полном
  инвентаре, обе руки, сохранность количества и компонентов, настоящий вызов размещения блока, отсутствие расхода.
  `buildertest fault` намеренно даёт один FAIL, затем обычный `buildertest` проходит без ошибок.
- Сервер с TFC 4.2.9 и Patchouli 93: 26/26 проверок, включая медные инструменты и загрузку рецепта.
  Начальная перезагрузка ресурсов печатает диагностические сообщения TFC о клиентских классах; сервер запускается,
  данные загружаются, проверки проходят.
- Клиент разработки: 6 проверок — синхронизация Curios, отсутствие обмена по ПКМ, перенос кирки из основного
  инвентаря, сохранность прежней стопки блоков на клиенте и сервере. Событие ввода вызывается проверочным модом;
  физическое удержание мыши человеком не проверяется.
- Ресурсы: MCP `resources_check`, `model_render`; обе локали, прозрачная текстура 16×16 по образцу очков Create. ImageGen-оригинал,
  описание и сравнение с поясом шахтёра в `art/`.

**В игре не проверялось:** реальное управление мышью, длительное строительство, поведение со всей сборкой,
удалённый многопользовательский сервер и совместимость с модами перемещения инвентаря.
