# EE Extras (`ee_extras`)

Аддон сборки для Create Electro Energetics (до 2.0 — «EE Rectifiers», `ee_rectifier`; старые блоки переходят на
новые id по псевдонимам). Общие правила разработки аддонов — [docs/addons.md](../../docs/addons.md); для игроков —
сайт, «Справочник → Аддоны».

| Блок / предмет | Клеммы | Внутри | Рецепт |
| --- | --- | --- | --- |
| Трёхфазный выпрямитель `three_phase_rectifier` | медные 0–2 — фазы, красная 3 — «+», синяя 4 — «−» | нагрузка треугольником + источник постоянного (1.1) | `CDC / DPD / DDD`: C — опорный изолятор EE, D — диод EE, P — `#c:plates/iron` |
| Однофазный выпрямитель `single_phase_rectifier` | медные 0 — фаза, 1 — нейтраль, красная 2 — «+», синяя 3 — «−» | нагрузка + источник постоянного (1.1) | `CDC / DPD / _D_` |
| Двусторонний преобразователь `bidirectional_converter` | медные; 0 «+», 1 «−» — заряд (сеть EE → FE), 2 «+», 3 «−» — разряд (FE → сеть EE); подписи — `ee_extras.nodes.*` | два преобразователя EE: нагрузка + источник с запасом, FE — с блока за задней гранью | 2 × преобразователь EE |
| Четырёхжильный соединитель `four_core_termination` | 1 L1, 2 L2, 3 L3, 4 N; узел 0 — кабель | только узлы | 2 × двухпроводной соединитель EE (и обратно) |
| Отвод фазы `four_core_tap` (2.1) | 1 фаза, 2 ноль; узел 0 — кабель | только узлы; для кабеля — «двухпроводной конец с выбором фазы», как соединитель EE | двухпроводной соединитель EE + изолированный провод |
| Изоляторы `duplex_cable_insulator`, `four_core_cable_insulator` | все узлы скрыты (0 — кабель, 1…n — жилы) | только узлы | опорный изолятор EE / 2 × (и обратно) |
| Катушка `four_core_cable_spool` | — | — | катушка двухпроводного кабеля EE + 8 изолированных проводов |

Всё ставится на любую из шести сторон, бывает в воде и масле. Соединители (свой четырёхжильный и двухпроводной EE)
ставятся выводом кабеля от игрока (на стене — вверх), ключ по лицевой грани — следующее из четырёх положений (у EE —
только крен, два из четырёх); соединитель EE с подключёнными проводами ключ не поворачивает (номера его узлов зависят от
положения — провода бы оборвались). Нужен на сервере и у
всех игроков. NeoForge 21.1.219+, Create 6.0.10, Electro Energetics 1.1.2+.

## Провода ЛЭП (2.1)

`lines/LineWire` — семь типов проводов EE (те же клеммы и изоляторы): медная шина, силовой кабель, М, АС, А, бронзовый,
ПС; числа и их смысл — в комментарии класса и на сайте. В EE нагрев зависит только от тока (предельный ток =
33,3 + предельная температура / 30), сопротивление — только потери, провис середины = 0,05 · sag · пролёт · f.
`lines/Tension` — натяжной зажим (навесная деталь EE + действие по клику на провод): натягивает провод до предела
материала (f = 0,2…0,6, длина = пролёт − (1 − f)); раз в 2 с проверка возвращает провода ЛЭП к допустимой длине (без
зажима — не короче пролёта). Железному проводу EE провис 1 → 0,6 (отражением, поле final). `lines/LinesClient` —
подсказки катушек (характеристики — механизмом EE через реестр подсказок Create). Графика и рецепты — `art/lines.py`.

## Устройство

- `EeExtras` — регистрация (блоки, предметы, устройства EE, типы проводов, блок-сущность), псевдонимы `ee_rectifier:*`,
  вкладка творческого режима EE. `Layout` — раскладки клемм (выпрямители, преобразователь, соединитель).
- Выпрямители — `RectifierBlock`, `RectifierDevice` (с 1.1 без диодов: резисторы входа, сопротивление пересчитывается
  каждый тик, выход — `energyLimitedSource` с запасом; подробности — комментарий в классе).
- `converter/` — двусторонний преобразователь. Формулы — как у `ConverterDevice` EE 1.1.2 (по байткоду): заряд — резистор
  max(20 Ом, U² / свободное место в запасе), разряд — `energyLimitedSource` с запасом, оба запаса до
  `converterMaxPowerKw`, перевод `wattFeTConversionRate`. FE: сначала через грань, которой касается сосед, потом
  через любую его грань, которая принимает (для заряда) или отдаёт (для разряда) — у конденсатора IE грань либо вход,
  либо выход. Сам блок тоже отдаёт возможность FE через заднюю грань (грань-выход конденсатора кладёт в разряд).
- `cable/` — кабели. В EE 1.1.2 катушка двухпроводного кабеля второй клик не обрабатывает; прокладку делает
  `CableLaying` (через `PlayerInteractEvent` для катушки EE и в `useOn` своей катушки). Кабель — оболочка (декоративный
  провод EE) и невидимые жилы; `CableData` следит, чтобы кабель не остался без части. Положения соединителей — `CableOrientation`
  (ROLL + 2·FLIP), подсветка и подпись вывода кабеля с катушкой в руке — `CableHud` (клиент). Подробности —
  [docs/addons.md](../../docs/addons.md), «Кабели EE».
- `mixin/BundledWirePreviewMixin` (клиент, 2.1.1) — исправление EE 1.1.2: предпросмотр кабеля (`BundledWireApplyingBehaviour.tick`)
  при выбранном первом конце и прицеле не на узел кабеля строил соединение с узлом null — вылет игры, если рядом
  есть хоть один провод. Узел под прицелом подменяется выбранным (соединения с собой не бывает). Мягкий, как и второй.
- Вкладка EE: аддон докладывает то, чего EE 1.1.2 туда не кладёт (двухпроводной соединитель и катушка; синхроскоп,
  частотомер, трёхфазные щётки — без `showACContent`), иначе их нет в JEI и поиске творческого режима.
- `mixin/WireVisualMixin` (клиент, переделан в 2.1.2) — исправление EE 1.1.2: отрисовку провода
  (`WireVisual.recreateInstances`) Flywheel зовёт из кадра и из обновления света в разных потоках одновременно, отрезки
  теряются из списка и остаются в мире «застывшими» (веер у качающейся гирлянды подвесных изоляторов до перезахода).
  Миксин пускает к проводу по одному потоку (обёрнуты `beginFrame`, `updateLight`, `delete` — без клиентских классов в
  сигнатуре, поэтому применение видно и на сервере разработки), запоминает все созданные проводом отрезки и удаляет
  те, что выпали из его списков. Мягкий: не применится — игра не падает; итог пишет в лог клиента `WireFixCheck`
  («исправление отрисовки проводов EE применено / НЕ применено»). В 2.1.0–2.1.1 был вариант с обёрткой
  `recreateInstances` — в игре веер остался, применился ли он, неизвестно (лога не было).
- `art/gen_assets.py` + `art/cables.py` — текстуры, модели, блокстейты (изоляторы и катушка — перекраска текстур EE
  из jar в `../../mods`). Иконки для сайта рисует общий генератор `scripts/mcp/render.mjs` (его вызывает `release.sh`).

## Сборка и проверка

```bash
./libs.sh          # Create и EE из ../../mods для компиляции (один раз и при обновлении сборки)
./release.sh       # ресурсы → сборка → проверка клемм → jar сюда и в ../../public/addons
./test-server.sh   # сервер разработки: выпрямители (минута-две)
IE=1 ./test-server.sh 'forceload add 0 0 64 80' 'rectest bidi' 'rectest bidipower 120 100' 'sleep 5' 'rectest bidireport'
./test-server.sh 'forceload add 0 0 64 80' 'rectest cables' 'rectest cablepower 100' 'sleep 4' 'rectest cablereport' 'rectest phase'
```

`IE=1` — добавить Immersive Engineering (конденсаторы), `KEEP=1` — не стирать мир (проверка после перезапуска),
`OLD_JAR=<jar>` — положить ещё и старую версию (переход со старых id). `JAVA_HOME` по умолчанию —
`~/.gradle/local-tools/jdk21` (см. docs/addons.md, «Среда»).

## Что проверено

**2.1 (2026-10-21), сервер разработки:** `./test-server.sh 'forceload add 0 112 80 170' 'rectest lines' 'sleep 1'
'rectest linespower' 'sleep 5' 'rectest linesreport'` — напряжение на нагрузке через 2 × 60 бл. каждого провода = расчёт
по сопротивлению (до 0,05 В); зажим на ПС — длина пролёт − 0,8, провис 0,24 бл. вместо 1,2; на медный EE не ставится;
укороченные провода ЛЭП возвращаются проверкой. Отвод фазы (`rectest cables`, `tap`, `cablepower 100`, `tapreport`,
`tapphase`): L1 → L2 → L3 → L1, фаза отвода = L1 только при L1. Клеммы: 372 из 372 (отвод — 24 положения).

**2.0.2 (2026-10-21), сервер разработки** (`./test-server.sh 'forceload add 0 76 48 100' 'rectest orient' 'sleep 3' 'rectest orientreport'`):

- Установка предметом от лица FakePlayer (настоящий путь через `EntityPlaceEvent`) на все 6 граней с 4 направлений
  взгляда — вывод у обоих соединителей там, где задумано; ключ — 4 разных положения и обратно в начальное; соединитель
  EE с проводом не поворачивается; четырёхжильный с кабелем поворачивается, кабель (оболочка + 4 жилы) остаётся.
- `check-nodes.sh`: 300 из 300 — клеммы четырёхжильного соединителя во всех 24 положениях и вывод, дорисованный
  соединителю EE, — точка кабеля EE во всех 24.
- Не проверено (нужен клиент): модель двухжильного кабеля, подсветка/подпись, что модели `assets/electroenergetics`
  аддона перекрывают модели EE (по коду FML: файлы модов идут в порядке сортировки с `ordering = AFTER`).

**2.0 (2026-10-21), сервер разработки:**

- `check-nodes.sh`: клеммы моделей = точки проводов во всех 12 положениях выпрямителей, преобразователя и
  четырёхжильного соединителя (216 из 216); на нарочно сдвинутой клемме проверка падает.
- Преобразователь на низковольтном конденсаторе IE: от батареи 120 В заряжает конденсатор (+14 FE/т сверх отданного)
  и одновременно держит 100 В на нагревателе (222 Вт); батарея выключена — нагрузка питается из конденсатора. Грани
  конденсатора: «касается — вход, север — выход», «касается — выход, север — вход» — работает; без грани-выхода
  разряд идёт, пока не кончится его запас.
- Двухжильный кабель соединитель EE → изолятор → соединитель EE: 99,7 В из 100 на нагревателе. Четырёхжильный
  соединитель → изолятор → соединитель: каждая фаза и ноль — как напрямую от батарей. Смешанный кабель к соединителю
  EE: ноль и фаза, ключ (`cyclePhase`) — L1 → L2 → L3 → L1 (вольтметр «фаза соединителя — L1»: 0 / 150 / 150 / 0 В).
  Творческие батареи EE со сдвигом фазы вольтметр показывает как 50 В при 100 В у батареи без сдвига — это видно и
  напрямую на батарее, не кабель.
- Сняли оболочку — жилы убрались, нагрузка обесточена; сломали изолятор — кабели к нему пропали. Перезапуск сервера:
  кабели, напряжения и выбранная фаза на месте.
- Мир с выпрямителями 1.1 (`ee_rectifier`) после перехода на 2.0 — блоки `ee_extras` в тех же положениях, с
  устройствами EE.

**Выпрямители 1.1** с настоящим генератором (`/rectest ac|acrpm|acwatch|acreport`, `MICROTICKS=N`): трёхфазный ровно
на 1–256 об/мин при microTicks = 1, вход = выход по мощности, перегрузка — устойчивая просадка, короткое замыкание —
сгорают провода. Однофазный на оборотах, кратных 64, ошибается. Версия 1.0 (диоды EE внутри) при microTicks = 1 была
нестабильна — см. `docs/plans/electricity.md`, «Диоды EE и переменный ток».

Не проверено: в игре с игроком (вид блоков и кабеля, «пунктир» катушки, установка катушкой, ключ, JEI/EMI) и
загрузка моделей клиентом — клиент на этой машине не запускался.
