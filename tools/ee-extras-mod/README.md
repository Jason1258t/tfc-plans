# EE Extras (`ee_extras`)

Аддон сборки для Create Electro Energetics (до 2.0 — «EE Rectifiers», `ee_rectifier`; старые блоки переходят на
новые id по псевдонимам). Общие правила разработки аддонов — [docs/addons.md](../../docs/addons.md); для игроков —
сайт, «Справочник → Аддоны».

Всё ставится на любую из шести сторон, бывает в воде и масле. Соединители (свой четырёхжильный и двухпроводной EE)
ставятся выводом кабеля от игрока (на стене — вверх), ключ по лицевой грани — следующее из четырёх положений (у EE —
только крен, два из четырёх); соединитель EE с подключёнными проводами ключ не поворачивает (номера его узлов зависят от
положения — провода бы оборвались). Нужен на сервере и у
всех игроков. NeoForge 21.1.219+, Create 6.0.10, Electro Energetics 1.1.2+.

## Провода ЛЭП (2.1)

`lines/LineWire` — семь типов проводов EE (те же клеммы и изоляторы): медная шина, силовой кабель, М, АС, А, бронзовый,
ПС; числа и их смысл — в комментарии класса и на сайте. В EE нагрев зависит только от тока (предельный ток =
33,3 + предельная температура / 30), сопротивление — только потери, провис середины = 0,05 · sag · пролёт · f.
`lines/Tension` — натяжной зажим (навесная деталь EE + действие по клику на провод): натягивает провод до предела
материала (f = 0,2…0,6, длина = пролёт − (1 − f)); раз в 2 с проверка возвращает провода ЛЭП к допустимой длине (без
зажима — не короче пролёта). Железному проводу EE провис 1 → 0,6 (отражением, поле final). `lines/LinesClient` —
подсказки катушек (характеристики — механизмом EE через реестр подсказок Create). Графика и рецепты — `art/lines.py`.

## Устройство

- `lantern/` (2.4) — фонарь IE в сети EE. `LanternConversion` (из `CableEvents`): клик катушкой двухпроводного кабеля
  по электрическому фонарю IE ставит `LanternBlock` в том же положении (IE facing=down — стоит, у нас FACING вверх;
  up — висит) и пускает клик в прокладку; с проводами IE — отказ (`IeWires`, API IE 12.4.2, классы IE грузятся только
  при фонаре IE в мире). Для кабеля — как изолятор: все узлы в гнезде провода IE ({8, 1, 8} лицом вверх, как
  `ElectricLanternBlockEntity.getConnectionOffset`), кабели жила к жиле. `LanternDevice` — резистор 1000 Ом, горит от
  50 В и ещё 40 тиков после (переменный ток проходит через ноль), `SpawnPreventingDevice` EE. Модели — фонаря IE по
  ссылке (`art/cables.py`, `lantern_blockstate`), выпадает фонарь IE, своего предмета нет; подсказка — на фонаре IE.
- `EeExtras` — регистрация (блоки, предметы, устройства EE, типы проводов, блок-сущность), псевдонимы `ee_rectifier:*`,
  вкладка творческого режима EE. `Layout` — раскладки клемм (выпрямители, преобразователь, соединитель).
- Выпрямители и инверторы — `PowerBlock` (до 2.2 — `RectifierBlock`), `RectifierDevice` (с 1.1 без диодов: резисторы
  входа, сопротивление пересчитывается каждый тик, выход — `energyLimitedSource` с запасом; подробности — комментарий в
  классе), `InverterDevice`. Ступени — `Tier` (лёгкий 6 кВт / тяжёлый 48 кВт, высота клемм; id тяжёлого — `heavy_` +
  id лёгкого). Нагрев (2.2) — `Heat`, формулы вариака EE 1.1.2 (по байткоду `VariacDevice.postTick`): тепло =
  мощность × 1300 / (номинал / 0,75), `ElectricalDevice.updateTemp` и `handleTemp` (дым 30 000, сгорание 40 000, в
  масле 60 000 / 80 000; только при `componentDamage`). Температура — `Temp` в `/cee device_data`.
- Инвертор (2.2, такт сети переделан в 2.5.1): вход — резистор (напряжение — среднее по микротикам со знаком), выход —
  `ac/Sine` на каждой паре фаз (у трёхфазного — треугольником), ЭДС = (π/3) × U пост. линейная (однофазный — (π/2)),
  внутреннее сопротивление — «10 % на номинал», не меньше ограничения запасом, как у `energyLimitedSource`. Такт — как
  у преобразователя частоты: `ac/Meter` по мгновенным напряжениям микротиков (в сборке microTicks = 8), режимы `off`
  (замер), `grid` (своя ЭДС выше сетевой; угол `predict(0)` и шаг — из замера, трёхфазный идёт за любым порядком фаз),
  `island` (своя синусоида 1 Гц, у трёхфазного порядок фаз генераторов EE — шаг < 0); сглаженная отдача < 0 — `off`.
  До 2.5.1 замер шёл по `getVoltageAt`, который при microTicks > 1 отдаёт действующее без знака, — в сборке инвертор
  к сети не подстраивался. В `/cee device_data` — `Mode`, `Amplitude`, `GridHz`, `PhaseError`.
- `ac/` — переменный ток (2.5): `Meter` — вектор стороны (амплитуда, угол, шаг за микротик) по мгновенным напряжениям
  микротиков (в сборке microTicks = 8, `getVoltageAt` там — действующее), `Sine` — источник синусоиды за
  сопротивлением на каждом микротике (как обмотки генератора EE), `FrequencyConverterDevice` (режимы no_input / wait /
  foreign / island / grid, звено с запасом как у инвертора), `SynchronizerDevice` (авто-включение, подгонка красным
  сигналом, защита), `AcBlock`/`SynchronizerBlock` (окно значения, сигнал — грань «быстрее» из положений клемм EE),
  `TallBaseBlock` + `TallBlockItem` (промышленный шкаф: устройство в верхнем блоке), `Cooling` (радиаторы, как у
  трансформатора EE), `AcBlocks` (регистрация). Модели — `art/acmachines.py`. Подробности EE — docs/addons.md,
  «Переменный ток EE».
- `generator/` — компактный генератор (2.3). Блок кинетический, как щёточный узел EE (`DirectionalKineticElectricBlock`,
  вал — только в задней грани), плюс крен, вода и масло, как у плит EE. Числа — от генератора EE 1.1.2 (по байткоду:
  выработка 48 × магниты × об/мин Вт, нагрузка на вал 48 × (магниты + 0,125) SU на 1 об/мин, ЭДС = выработка / 100 А):
  8 SU на 1 об/мин (`BlockStressValues.IMPACTS`), 6 Вт и 0,5 В на 1 об/мин, номинал нагрева 1,2 кВт. Устройство
  `GeneratorDevice` — как `GeneratingDevice` EE (запас ≤ 10 тиков мощности, `energyLimitedSource`); приток каждый тик
  ставит блок-сущность (неизрасходованное пропадает, как у EE). Полувал на клиенте — `GeneratorClient`
  (`OrientedRotatingVisual` / `KineticBlockEntityRenderer` с `SHAFT_HALF`, смотрит назад).
- `converter/` — двусторонний преобразователь. Формулы — как у `ConverterDevice` EE 1.1.2 (по байткоду): заряд — резистор
  max(20 Ом, U² / свободное место в запасе), разряд — `energyLimitedSource` с запасом, оба запаса до
  `converterMaxPowerKw`, перевод `wattFeTConversionRate`. FE: сначала через грань, которой касается сосед, потом
  через любую его грань, которая принимает (для заряда) или отдаёт (для разряда) — у конденсатора IE грань либо вход,
  либо выход. Сам блок тоже отдаёт возможность FE через заднюю грань (грань-выход конденсатора кладёт в разряд).
- `cable/` — кабели. В EE 1.1.2 катушка двухпроводного кабеля второй клик не обрабатывает; прокладку делает
  `CableLaying` (через `PlayerInteractEvent` для катушки EE и в `useOn` своей катушки). Кабель — оболочка (декоративный
  провод EE) и невидимые жилы; `CableData` следит, чтобы кабель не остался без части. Положения соединителей — `CableOrientation`
  (ROLL + 2·FLIP), подсветка и подпись вывода кабеля с катушкой в руке — `CableHud` (клиент). Подробности —
  [docs/addons.md](../../docs/addons.md), «Кабели EE».
- `mixin/BundledWirePreviewMixin` (клиент, 2.1.1) — исправление EE 1.1.2: предпросмотр кабеля (`BundledWireApplyingBehaviour.tick`)
  при выбранном первом конце и прицеле не на узел кабеля строил соединение с узлом null — вылет игры, если рядом
  есть хоть один провод. Узел под прицелом подменяется выбранным (соединения с собой не бывает). Мягкий, как и второй.
- Вкладка EE: аддон докладывает то, чего EE 1.1.2 туда не кладёт (двухпроводной соединитель и катушка; синхроскоп,
  частотомер, трёхфазные щётки — без `showACContent`), иначе их нет в JEI и поиске творческого режима.
- `mixin/WirePointsRawMixin` (2.3.3) — настоящая причина веера у гирлянды подвесных изоляторов: в EE 1.1.2
  `QuadraticWireHelper.wirePointsRaw` дописывает точки в буфер провода, не очистив его, и Flywheel рисует все прошлые
  положения качающейся гирлянды. Миксин очищает буфер в начале метода. Команда `/eeextras wires` (`WireDiag`, клиент) —
  замер проводов EE, отрисовок и кусков Flywheel; ею причина и найдена.
- `mixin/WireVisualMixin` (клиент, переделан в 2.1.2) — исправление EE 1.1.2: отрисовку провода
  (`WireVisual.recreateInstances`) Flywheel зовёт из кадра и из обновления света в разных потоках одновременно, отрезки
  теряются из списка и остаются в мире «застывшими» (веер у качающейся гирлянды подвесных изоляторов до перезахода).
  Миксин пускает к проводу по одному потоку (обёрнуты `beginFrame`, `updateLight`, `delete` — без клиентских классов в
  сигнатуре, поэтому применение видно и на сервере разработки), запоминает все созданные проводом отрезки и удаляет
  те, что выпали из его списков. Мягкий: не применится — игра не падает; итог пишет в лог клиента `WireFixCheck`
  («исправление отрисовки проводов EE применено / НЕ применено»). В 2.1.0–2.1.1 был вариант с обёрткой
  `recreateInstances` — в игре веер остался, применился ли он, неизвестно (лога не было).
- `art/gen_assets.py` + `art/cables.py` — текстуры, модели (тяжёлые — `heavy_model`: корпус, рёбра-радиаторы по сторонам
  без клемм, проходные изоляторы с шапками; текстура — верх лёгкой + `heavy_parts`), блокстейты (изоляторы и катушка — перекраска текстур EE
  из jar сборки — кеш снимка, `npm run pack:fetch`). Иконки для сайта рисует общий генератор `scripts/mcp/render.mjs` (его вызывает `release.sh`).

## Сборка и проверка

```bash
./libs.sh          # Create и EE из jar сборки (кеш снимка, npm run pack:fetch) для компиляции (один раз и при обновлении сборки)
./release.sh       # ресурсы → сборка → проверка клемм → jar и иконки (icons/) сюда; на сайт — сборкой сайта
./test-server.sh   # сервер разработки: выпрямители (минута-две)
./test-server.sh 'forceload add 112 0 150 60' 'rectest heat 3' 'sleep 1' 'rectest heatv 300' 'sleep 30' 'rectest preport'
./test-server.sh 'forceload add 112 0 150 60' 'rectest grid 8' 'sleep 1' 'rectest dc 85' 'sleep 6' 'rectest pwatch 8' 'sleep 1' 'rectest preport'
IE=1 ./test-server.sh 'forceload add 0 0 64 80' 'rectest bidi' 'rectest bidipower 120 100' 'sleep 5' 'rectest bidireport'
./test-server.sh 'forceload add 150 -10 180 20' 'rectest kgen 64 10' 'sleep 4' 'rectest kreport' 'rectest krpm 256' 'sleep 4' 'rectest kreport'
IE=1 ./test-server.sh 'forceload add 0 110 32 130' 'rectest lanterns' 'rectest lanternpower 230' 'sleep 3' 'rectest lanternreport' 'rectest lanternie'
MICROTICKS=8 ./test-server.sh 'forceload add 96 96 130 125' 'rectest fc 64 light' 'sleep 3' 'rectest fchz 16' 'sleep 4' 'rectest fcpar' 'sleep 4' 'rectest fcreport'
MICROTICKS=8 ./test-server.sh 'forceload add 96 128 140 160' 'rectest sy 64 0' 'sleep 3' 'rectest syrpm 64 64' 'sleep 20' 'rectest syreport'
./test-server.sh 'forceload add 0 0 64 80' 'rectest cables' 'rectest cablepower 100' 'sleep 4' 'rectest cablereport' 'rectest phase'
```

`IE=1` — добавить Immersive Engineering (конденсаторы), `KEEP=1` — не стирать мир (проверка после перезапуска),
`OLD_JAR=<jar>` — положить ещё и старую версию (переход со старых id), `RCON_PORT=…`/`SERVER_PORT=…` — другие порты, если рядом идёт такой же сервер из другого ворктри. `JAVA_HOME` по умолчанию —
`~/.gradle/local-tools/jdk21` (см. docs/addons.md, «Среда»).

## Что проверено

**2.5.1 (2026-10-29), сервер разработки** (`rectest grid|dc|pwatch|preport|island`, `src/devtest/.../Power.java`,
теперь с частотомерами EE): инвертор переведён на `Meter` + `Sine`. `MICROTICKS=8`, генератор 64 об/мин (10 Гц, 448 В
линейное): трёхфазный один на сети — 600 В пост. `off`, 640 В — 0,63 кВт, 670 В — 5,2 кВт ровно, вход = выход,
`PhaseError` 0,0°, частотомер сети 10,00 Гц; однофазный — 220 В `off`, 240 В — 0,14 кВт, 250 В — 3,3 кВт, 0,0°. Без
сети от 300 В: частотомеры EE — 1,00 Гц у обоих, трёхфазный 2,95 кВт ровно, однофазный пульсирует с двойной частотой;
после перезапуска (`KEEP=1`) — снова `island` 1,00 Гц. `MICROTICKS=1`, 8 об/мин (1,25 Гц): трёхфазный 60 В `off`,
80 В — 0,27 кВт, 86 В — 2,9 кВт, < 0,1°; однофазный 24 В `off`, 32 В — до 0,7 кВт, < 0,5°. Оба сразу на слабом
генераторе 8 об/мин при 86 В: однофазный на ~4 номиналах перетягивает сеть (частота уходит) — перегрузка, не такт.
Не проверено: клиент, несколько инверторов на одной сети, двигатели вместо нагревателей.

**2.5 (2026-10-29), сервер разработки, `MICROTICKS=8`** (`src/devtest/.../Sync.java`): генератор 64 об/мин →
