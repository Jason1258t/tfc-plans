# Create: Stress Fix (`stress_fix`)

Аддон для Create 6.0.10: сеть вращения не копит «фантомную» нагрузку и мощность при перезаходе в мир.

## Что было

После перезахода некоторые водяные колёса вставали, а сеть показывала нагрузку в миллионы SU, хотя все колёса вместе
дают около 33 000 SU. Сеть считалась перегруженной, вращение останавливалось.

## Почему (по байткоду Create 6.0.10 и на сервере разработки)

Create при загрузке не пересчитывает сеть вращения с нуля:

- Каждый блок сети при сохранении запоминает итог всей сети: мощность, нагрузку и число блоков
  (`KineticBlockEntity.write`, тег `Network`).
- Первый загрузившийся блок сети отдаёт эти числа сети как «незагруженную часть» (`KineticNetwork.initFromTE`).
- Каждый следующий блок при загрузке вычитает из неё свой вклад и добавляется уже как живой (`addSilently`).

Если запомненное разошлось с тем, что блоки вычитают при загрузке, остаток навсегда остаётся в учёте как мощность или
нагрузка «где-то в незагруженных чанках». Так бывает, если чанк сохранился со старыми числами, вклад колеса при
загрузке стал другим (у Picky Wheels он зависит от воды и биома) или блок убрали без пересохранения сети. При
следующем сохранении остаток попадает в итог сети, после перезахода опять остаётся — и копится.

На сервере разработки это воспроизведено без аддона: в сеть «творческий мотор → валы → вентилятор» подложена нагрузка
3 000 000 SU, мир сохранён и запущен заново. Фантом пережил перезапуск, сеть перегружена, скорость 0.

Какой именно мод или случай сбил числа у группы, по логам не установлено. Аддон убирает следствие — накопленный
остаток — при любом источнике.

## Что делает аддон

Раз в секунду проверяет сети, у которых учёт незагруженной части не пуст. Если у каждого живого блока сети все соседи,
с которыми Create может соединить вращение (шесть сторон и дальние связи — большие шестерни, цепные приводы и т. п.,
как у самого Create), стоят в работающих (тикающих) чанках и уже записаны в сеть, — незагруженной части у сети нет.
Тогда остаток ни к какому блоку не относится: аддон его обнуляет, пересчитывает сеть и пишет в лог сервера:

```
Сеть вращения у X, Y, Z: убран фантом незагруженной части — мощность … SU, нагрузка … SU, блоков … (живых блоков в сети …)
```

Если хоть часть сети в незагруженном или нетикающем чанке, сеть не трогается: Create сам учитывает эту часть,
пока её нет.

Проверять «чанк тикает», а не «чанк загружен» пришлось после проверки: между тиками Minecraft ещё отвечает
«загружен» по только что выгруженному чанку.

## Команды (уровень оператора 2)

- `/stressfix` — сети текущего измерения с непустым учётом незагруженной части: сколько там висит, загружена ли сеть
  целиком. Загруженные целиком — чистит сразу.
- `/stressfix recalc` — то же для всех сетей и заново спросить у живых блоков их вклад (на случай, если колесо
  «забыло» обновить свой вклад).

`-Dstress_fix.disabled=true` в параметрах Java — выключить автоматическую очистку (команды работают).

## Кому ставить

Логика только на сервере. Ставить на сервер и хосту (в «мире хоста» сервер работает в его программе). Остальным
игрокам не нужен, но и не мешает: новых блоков нет, войти на сервер можно и без него.

## Сборка и проверка

- `./libs.sh` (один раз, `MODS=<папка>` — другая папка модов), `./gradlew build` или `./release.sh`.
- `./test-server.sh` — сервер разработки (NeoForge 21.1.219 + Create 6.0.10, плоский мир) в три запуска:
  1. аддон выключен — подложить фантом и сохранить;
  2. аддон выключен — фантом пережил перезапуск;
  3. аддон включён — фантом убран через секунду; сеть через выгруженные чанки не тронута, пока их не загрузят.

  Проверочный мод (`src/devtest`) — `/sftest report|phantom`.

Новая версия Create (зависимость `[6.0.10,6.1)`): сверить поля `KineticNetwork` (`unloadedCapacity`, `unloadedStress`,
`unloadedMembers`) и `TorquePropagator.networks`, а заодно проверить, не исправили ли учёт сами.
